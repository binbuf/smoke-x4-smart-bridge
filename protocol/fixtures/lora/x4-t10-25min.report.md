**Board:** Heltec WiFi LoRa 32 V3 · COM5 · IDF 6.0.2
**Capture image:** `firmware/bench/t10_probe/` (throwaway; vendored `ra01s`)
**Device:** `LMXC[\` · operating channel **918,500,000 Hz**
**Fixture:** `x4-t10-25min.loralog`

## What was done

The probe listened on the 915.0 MHz sync channel. When the Smoke X4 was put
into sync it captured this beacon:

```
000000,LMXC[\,160,50,191,54,
```

It decoded the operating frequency (918.5 MHz), retuned, and sent the one
allowed ACK on that frequency:

```
LMXC[\,SUCCESS,          (tx, 143005 ms)
```

The stock receiver was then synced as well; its own ACK was captured on
918.5 MHz:

```
LMXC[\,SUCCESS,          (rx, 308984 ms)
```

From then on the X4 sent 26-comma state frames at the normal ~30 s cadence.

## Deviation

T10 asks for **30+ minutes** of state traffic. This capture has **22.4 minutes**
of state traffic (41 frames) because the owner chose to stop after all required
event types were captured. The sync beacon, our ACK, the stock receiver ACK,
four-probe state, detach/reattach and °F→°C→°F are all present. The missing
7.6 minutes would only add more steady-state frames; no event type is absent.

The exact receiver button gesture was not separately recorded. The stock
receiver completed its normal sync procedure and its ACK is in the capture;
the manual documents holding the receiver's **VOL** button for 5 seconds.
