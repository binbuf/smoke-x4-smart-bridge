## What landed

- `app/lib/data/ble/bridge_protocol.dart`
  - V0 slice of the generated contract in `lib/`: characteristic UUIDs,
    `live`, `control` + `set_time` body, `result`, `sync_ctrl`, sync frame
    header, START/END and the 18-byte record (24-bit seq, u32 unix_s).
  - `BridgeResultAssembler` (MTU-split result, first chunk carries the 5-byte
    header) and `BridgeSyncAssembler` (MTU-split frames → START/RECORDS/END).
- `app/lib/data/ble/bridge_link.dart`
  - The fixed procedure: connect → read `info` → MTU 247 → bond when not
    secured → subscribe `live`/`result`/`sync_data` → read `live` →
    `control(set_time)` → sync. `completeFirstConnect(device)` starts after the
    setup bond; `connectAndSecure(device)` runs the full order for a fresh link.
  - Control queue: non-reused 0–255 `op_id`, 3 s timeout, match on op + op_id,
    branch on `result.status`; write rejection maps to `bondRequired` and takes
    the bond path once.
  - `set_time` with phone UTC ms + `tz_offset_min`; first connect always sets;
    reconnect compares wall-clock vs monotonic elapsed since the last set and
    re-sends when `clock_valid` is false or the difference exceeds 2 s.
  - Reconnect backoff 1/2/4/8/15/30 s, cancellable wait for pull-to-refresh and
    app resume, `FAILED` after six attempts.
  - Health watchdog 110 s → read `live`; fresh → LIVE, quiet → STALE, failure →
    RECONNECTING. Any GATT disconnect → RECONNECTING.
  - Recent sync is backward over the **last 15 minutes**; reconnect syncs
    forward from `localMaxSeq` (never a 24 h re-read). Batches go to a
    `BridgeSyncSink` (no-op in V0) and the cursor to `onLocalMaxSeq`.
- `app/lib/app/bridge_controller.dart`
  - `ensureLink(...)` builds and wires `BridgeLink`, with test seams for clock,
    elapsed time, wait, timer and sync sink.
  - Live receipt time (`liveReceivedAt`), live probe temp override, info →
    device/firmware/protocol/`billowsObserveCap`, sync state, reconnect attempt
    counters, `localMaxSeq`.
  - `refreshLink()` (pull-to-refresh) and `onAppResume()`.
  - Product copy: `Syncing saved readings · last 15 minutes`; reconnect copy

- `app/lib/features/setup/setup_flow.dart`: `_afterBond` now runs the real

- `app/lib/features/live/live_screen.dart`: pull-to-refresh calls

## Deviations / decisions

- The bridge clock is not readable in V0 (stats is out of scope). Reconnect
  compares the phone's wall clock with monotonic elapsed time since the last
  successful `set_time`; `live.clock_valid` forces a reset after a bridge power
  loss. See ADR 0042.
- The procedure bonds proactively when `bondState` is not bonded, rather than
  deliberately reading `live` to provoke ATT `0x0F`. Any security failure on a
  read/write still takes the same one-shot bond path and never loops.
- Recent sync advances the local cursor to the bridge max even when older
  records fall outside 15 minutes. That is deliberate V0 skip semantics; the
  background/older load belongs to T39–T41.
- A reconnect-time re-pair has no approved passkey surface yet; `bond()` is
  called with the OS dialog. Setup still owns the "look at the Bridge screen"
  instruction before the first bond.

## Gotchas for later tasks

- **T36/T39–T41:** consume `BridgeSyncBatch` through `BridgeSyncSink`; replace
  `controller.localMaxSeq` with the durable cursor. The recent pass is backward
  and already filtered to 15 minutes.
- **T36:** `controller.liveProbeTemps` and `liveReceivedAt` are the live receipt
  seam; `smokeXAgeOverride` still wins when tests set it.
- **T37/T48:** a reconnect after a stale bond needs the approved passkey
  instruction and `Forget this phone` should also remove the OS bond.
- **T40/T47:** replace `bridge_protocol.dart` with the packaged generated codec;
  `test/link_codec_test.dart` is the drift guard to delete then.
- **Widget tests:** a completed first connect arms a real 110 s timer. Call
  `controller.link?.dispose()` (or discard the future) inside the test body, not
  only in `addTearDown`, or `flutter test` fails with a pending timer.
- **Test seams:** `ensureLink` accepts `settings`, `sink`, `nowUtc`, `elapsed`,
  `wait`, `schedule` and `bondPrompt`; `bridge_link_test.dart` has a manual
  clock/timer that avoids the 60 s backoff wait.
- **Fake:** `FakeBleClient.operations` records call order; `FakeBridge` captures
  `controlWrites`/`syncRequests` and supports `dropControlResults`,
  `forcedControlStatus`, `clockValid` and `addRecord`.
- The forward cursor is inclusive (`cursorSeq = localMaxSeq`) and the duplicate
  newest record is deduped on accept. T39 should confirm the exclusive-cursor
  semantics against the archive.
