## What landed

- `app/lib/data/ble/ble_client.dart`
  - `BleClient` gains `platformStatus()`, `requestPermissions()`,
    `removeBond()` and `diagnostics`; scan/connect/bond/MTU/read/write/notify
    keep the T07 shape.
  - Named state model: `BlePermissionState` (not determined, granted, denied,
    permanently denied), `BlePermissionKind` (nearby devices vs location),
    `BlePlatformStatus`, `BleAppState` (06 §6.8), `BleRecoveryAction`, and
    `BleFailure.appState` / `BleAppState.recoveryAction`.
  - `BleException` carries a `BleFailure` and exposes `appState` /
    `recoveryAction`. `exceptionForBleAppState` converts a blocked snapshot into
    the typed throw used by scan/connect.
  - Production constants pinned to the generated contract:
    `bleContractServiceUuid` (`7f9b0000-…`), `bleClientLocalNamePrefix`,
    `bleRequestedMtu` 247, `bleDefaultMtu` 23, `bleScanTimeout` 10 s.
  - `selectPreferredBridge` matches remembered device ID then name and returns
    `null` rather than an arbitrary first result. `orderBridgesForDisplay` puts
    the remembered bridge first. `BleDevice.isCompatibleBridge` requires both
    the contract service UUID and the `SmokeX4-` name, so a legacy `7f9a…`
    advertisement is never selectable.
  - `BleDiagnostics` records a bounded log (scan/connect/bond/MTU failures) plus
    phone model, Android version and negotiated MTU.
- `app/lib/data/ble/ble_error_mapper.dart`
  - `mapBlePlatformError(error, operation)` maps `FlutterBluePlusException`,
    native GATT statuses, `TimeoutException`, `PlatformException`,
    `ArgumentError`/`FormatException` and unknown errors to `BleException`.
  - Native GATT statuses are disambiguated from FBP's small error codes by the
    platform marker. 5/15/2/3 → not bonded, 8 → timeout, 133 → connection or
    GATT error, 19/22 → connection failed.
- `app/lib/data/ble/flutter_blue_plus_ble_client.dart`
  - Real client on `flutter_blue_plus` 1.35.12 and `permission_handler` 11.4.0.
    Only this file imports either plugin.
  - `platformStatus` checks hardware, adapter then permission. Android 12+
    checks/requests `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT`; API 30 and below
    checks/requests location.
  - Scan filters the contract service UUID, dedupes by device ID, stops at 10 s,
    and maps start/stream errors to `scanFailed` → no-results.
  - Connect/disconnect, `createBond`/`removeBond`, MTU request, read, write and
    subscribe. Long-read fallback: if a read fills the ATT payload at MTU < 247,
    request 247 and re-read once (the plugin has no Read Blob offset API). This
    is what makes the 32-byte `info` readable at MTU 23.
  - Debug phone info comes from a `smoke_bridge/device_info` method channel in
    `MainActivity.kt`; a missing channel falls back to the Dart platform
    version.
- `app/android/app/src/main/AndroidManifest.xml`: `BLUETOOTH_SCAN` with
  `neverForLocation`, `BLUETOOTH_CONNECT`, and `ACCESS_FINE/COARSE_LOCATION`
  capped at `maxSdkVersion="30"`; BLE feature not required so unsupported phones
  reach the named state.
- `app/test/support/fake_ble_client.dart`: implements the expanded interface,
  records diagnostics and accepts scripted permission/adapter/support state and
  per-operation faults (`scanError`, `connectError`, `bondError`, `readError`,
  `writeError`, `notifyError`, `mtuError`, `removeBondError`).
- `app/test/ble_client_mapping_test.dart` (22 tests): every `BleFailure` and
  `BleAppState` mapping/recovery action, plugin exception injection, native GATT
  codes, no raw error string, selection rules, legacy UUID rejection, fake
  faults, bond states, MTU diagnostics, and `FakeBleClient` satisfying
  `BleClient`.
- Docs: `docs/design/adr/0039-platform-ble-client-and-named-states.md`,
  `docs/design/06-app.md` §6.9/§6.10.

## Deviations / decisions

- `flutter_blue_plus` is pinned to **1.35.12**, the last BSD-3 line. 2.x requires
  a paid commercial licence; upgrading is a licensing decision (ADR 0039).
- The plugin has no Read Blob API. T32 implements a long-read fallback (raise
  MTU to 247 and re-read once). The fixed payloads fit at 247; a controller that
  caps below 247 still yields a short read, which the codec treats as an error.
- Android cannot distinguish "never requested" from "permanently denied" on a
  status check. `platformStatus` reports `denied`; `requestPermissions` reports
  `permanentlyDenied` and the UI then maps to the blocked state.
- Verification used `flutter_blue_plus` 1.35.12; 2.x API differences (`license:`,
  `connect`/`bond` changes) do not apply.
- The real client does not auto-request MTU during `connect`; it exposes
  `requestMtu(247)` for T35's fixed procedure order and only renegotiates inside
  `read` when a short ATT read is detected.

## Gotchas for later tasks

- **T33 owns the UI.** Use `platformStatus().state`, `requestPermissions()`,
  `BleAppState.recoveryAction` and the approved copy. Do not import the plugin.
- **T35 owns the procedure order.** Connect → read `info` → `requestMtu(247)` →
  bond → subscribe → read `live` → set time → sync. The client's read fallback
  may negotiate 247 early; a later explicit request is idempotent.
- **T33/T35: selection.** Use `selectPreferredBridge`/`orderBridgesForDisplay`;
  do not connect to `results.first`.
- **T33:** call `requestPermissions` after the primer only. On API 31+ it does
  not request location; on API 30- it does.
- **T35:** `notBonded` maps to a pairing state; treat it as "bond first", not a
  fatal GATT error, and do not retry forever.
- **T35:** ATT MTU 23 sync still works but is slow; `diagnostics.negotiatedMtu`
  is the value to show in Bridge details.
- **T34/T36:** `notifications()` controllers exist before `setNotify`; enable
  the CCCD with `setNotify(uuid, enabled: true)` first.
- **Tests:** `FakeBridge.advertisement()` uses device id `fake-A4F2`;
  `FakeBleClient.connect` only accepts an advertised id.
- **Android build:** the plugin adds a Kotlin/Java compile; `flutter analyze`
  does not prove the manifest/native channel. `flutter build apk --debug` is the
  cheap guard.
