**Date:** 2026-10-26 · **Board:** Heltec WiFi LoRa 32 V3 · COM5 · IDF 6.0.2
**Result:** code and host checks complete; the real-X4 board log check is

## What landed

- `firmware/components/sx_radio/sx_radio.c` — real SX1262 bring-up and the
  `radio_rx` task. `LoRaBegin(915 MHz, 22 dBm, 3.3 V TCXO, LDO)` then
  `SetSyncWord(0x12)` and `LoRaConfig(9, 4, CR 4/5, preamble 10, explicit
  header, CRC on, no IQ invert)`. The task is created with the design budget
  (4096 bytes, priority 6, core 1) and polls with `vTaskDelay(1)`.
- The RX read does **not** call the driver's `LoRaReceive()`/`ReadBuffer()`:
  those `malloc` per packet. It calls `GetRxBufferStatus`, `spi_read_byte`, and
  `GetPacketStatus` with a fixed 128+3-byte static scratch buffer.
- `firmware/components/sx_radio/include/sx_radio_params.h` — the single
  parameter block (SF/BW/CR/preamble/sync/CRC/TCXO/LDO/902–928 MHz/task
  budget). No magic numbers in the task.
- `firmware/components/sx_radio/include/sx_radio_rx.h` +
  `sx_radio_rx.c` — pure-C host-injectable parser seam. `publish` copies into
  a fixed SPSC queue (4 slots, capacity 3): no allocation, never blocks; full
  queue drops the newest frame and counts it. Consumers use
  `sx4_radio_rx_take()`.
- `firmware/components/sx_radio/include/sx_radio.h` — adds
  `sx_radio_set_frequency()` (validates 902–928 MHz before retuning) for T16.
- `firmware/test/test_sx_radio_rx.c` — injects a literal X4 state frame, edge
  cases (NULL/empty/129 bytes) and a real `x4-t10-25min.loralog` state packet,
  then observes length/RSSI/SNR/bytes at the seam. Also checks the parameter
  block, frequency bounds and the task budget macros.
- `firmware/test/test_tasks.c` — now pins `radio_rx` to 4096 bytes,
  priority 6, core 1.
- Docs: ADR 0021; design 03 §3.14; host-test README.

## Gotchas for later tasks

- `firmware/vendor/.../ra01s.c` `ReadBuffer()` allocates. Do not call
  `LoRaReceive()` from the RX path; use the public primitives already in
  `sx_radio.c` or add a no-alloc helper in `sx_radio`.
- `LoRaConfig()` does not set the sync word. `SetSyncWord(0x12)` is required
  after `LoRaBegin()`.
- The driver's `SetRx()` re-arms continuous RX and is called after every packet
  or CRC/header error.
- `sx_radio_init()` resets the seam. `sx_radio_set_frequency()` validates the
  902–928 MHz range and retunes only when configured; T16 is the intended
  caller.
- The board default remains 915 MHz until T16 applies the persisted pairing
  record. A paired X4 on 918.5/910.5 will **not** be received before T16.
- Board environment: `export.ps1` defaults to the py3.12 env, whose
  `esp-idf-monitor` is too old. Set `IDF_PYTHON_ENV_PATH` to
  `...\idf6.0_py3.13_env` first.
- Serial capture helper used this session:
  `C:\Users\dan\AppData\Local\Temp\opencode\capture_com5.py COM5 <seconds>`
  (opens at 115200, DTR low, RTS pulse reset, writes raw bytes).
- Fixture path in host tests: `SX4_FIXTURE_DIR` is set by
  `firmware/test/CMakeLists.txt` to `protocol/fixtures/lora`.
