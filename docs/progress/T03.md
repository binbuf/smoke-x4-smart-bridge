# T03 — Host test harness and fixtures

## What landed

- `firmware/test` plain CMake/C11 project; `ctest` is the entry point.
  - `records` compiles `protocol/test/test_records.c` directly against
    `protocol/gen/records.c` (re-exported as `sx4_protocol_gen`).
  - `lora-corpus` loads real captures + `parser-vectors.tsv` and checks corpus
    shape, known X4 values, malformed rejection, metadata and coverage.
  - `log-io-ram` tests the RAM fake: geometry, bounds, erase, counters,
    one-shot failure injection, torn writes/erases.
- `firmware/test/support/`: `test_util`, `lora_corpus`, `ram_log_io`.
- `firmware/components/sample_log/include/log_io.h`: byte-oriented
  `read`/`write`/`erase` seam, capacity/sector size, `LOG_IO_ERR_*`.
- Fixtures copied unchanged from `legacy/protocol/fixtures/lora/` to
  `protocol/fixtures/lora/`:
  `x4-events-10min`, `x4-passive-session`, `first-x4-contact`, `malformed`,
  and the three reports. `README.md` records provenance.
- `protocol/fixtures/lora/parser-vectors.tsv`: 20 rows, 11 tab-separated
  columns (name, category, kind, probes, expect, device_id, units, attached,
  frequency, provenance, payload).
- `make host-test` wrapper; ADR 0014; notes in design 02 §2.9, 03 §3.13/§3.14,
  10 §10.2.

## Key facts for later tasks

- Build: gcc 16.1.0 + cmake 4.4.3 + ninja on this bench. `gcc`/`ninja` live in
  `C:\msys64\ucrt64\bin`; prepend that to `PATH` for PowerShell. `make` is
  `C:\msys64\usr\bin\make.exe`.
- `ctest` names are `records`, `lora-corpus`, `log-io-ram`. Build output is
  `firmware/test/build` and is ignored by the bare `build/` rule.
- `SX4_FIXTURE_DIR` is a compile definition with an absolute path to
  `protocol/fixtures/lora`; tests do not depend on the working directory.
- Corpus loaders:
  - `sx4_loralog_read(path, lines, max, &count)` parses `boot t_ms rssi snr dir
    class payload`; `?` RSSI/SNR becomes 127/0.
  - `sx4_vectors_read(path, vectors, max, &count)` parses the TSV. Sync reject
    rows may use `-` for frequency; state rows must use `-`.
  - `sx4_vector_t.probes` is 0 for sync, 2/4 for state; `attached_mask` bit 0
    is probe 1.
- Fixture wire rules used by the tests: state comma count = `6 + 5*probes`;
  sync = 6; valid payloads are < 128 bytes and end with `,`. Probe temp/alarm
  fields are int16, values `<= INT16_MIN + 1` are sentinel collisions.
- Real capture facts asserted by the suite: events has 1 sync, 1 ack, 36+
  states, 3 alarm edges, 3 frozen detached probes, 918.5 MHz,
  `LMXC[\`; passive has 54+ states and no alarms; all state header field 1 is
  30.
- `parser-vectors.tsv` categories: `x4`, `x2-defensive`, `malformed`,
  `foreign-id`, `detached`, `celsius`, `billows`, `out-of-range`.
- `log_io` seam: `log_io_t` holds `ops`, `ctx`, `capacity`, `sector_size`.
  `log_io_erase` requires sector-aligned offset/length (the RAM fake enforces
  it; T19's adapter should too). `log_io_read`/`write` of length 0 are no-ops.
- `ram_log_io_fail_next(ram, op, bytes)` is one-shot; for read/write/erase it
  commits only `bytes` of the request then returns `LOG_IO_ERR_IO`. This is the
  torn-tail seam for T18.
- Do not add `protocol/fixtures/lora/` to `.gitignore`; it is committed test
  data. Never make tests read `legacy/` (it is ignored and absent in a clean
  clone).
