# T21 — sample_pipe: parser → log → UI

**Date:** 2026-10-26 · **Verification:** host/CI (no board) · **Result:** done

## What landed

- `firmware/components/sample_pipe/include/sample_pipe.h` — pure-C pipeline
  API: `sample_pipe_t`, `sample_pipe_io_t` callbacks, `sample_pipe_pending_t`,
  counters, and the `sample_pipe_process()` / `sample_pipe_complete()` split.
- `firmware/components/sample_pipe/sample_pipe.c` — the core:
  - classifies a frame by comma count (2 = ACK ignored, 6 = sync beacon counted,
    16/26 = state);
  - loads the persisted pairing through a callback; unpaired state frames are
    ignored (discovery stays T16's job);
  - parses state with `sx_protocol_parse_state()` and the persisted ID, counts
    foreign IDs separately from parse failures;
  - builds one 18-byte record plus a `bridge_state_sample_t`: attached mask,
    detached sentinel, °F tenths, Billows attach/alarm/Celsius flags;
  - persists the learned probe count once via `save_probe_count` when it differs
    from the stored pairing (T15 `bridge_config_set_pairing`);
  - stamps the record through `bridge_state_stamp_record` and validates the
    layout before queueing;
  - uses only stack/static memory; no ESP-IDF, no malloc.
- `firmware/components/sample_pipe/sample_pipe_esp.c` — firmware wiring:
  - static FreeRTOS queue of `SAMPLE_PIPE_LOG_QUEUE_DEPTH` (8) pending samples;
  - `sample_pipe` task (4096/5/core 0) drains `sx4_radio_rx_take()`;
  - `log_writer` task (4096/4/core 0) calls `sample_log_append()`, then
    `sample_pipe_complete()`, then `bridge_state_tick()` and the storage flag;
  - enqueue is zero-tick `xQueueSend`: full queue = drop + counter, no stall.
- `firmware/components/ui/` — `ui_mark_dirty()`, `ui_dirty_take()`,
  `ui_dirty_pending()` (C11 atomic; T22 consumes).
- `firmware/main/boot.c` + `main/CMakeLists.txt` — `sample_pipe_start()` runs
  after `sx_radio_init` and before `sx_radio_start`.
- `firmware/components/sx_radio/sx_radio.c` — CRC and header errors now call
  `sx_protocol_note_crc_failure()`.
- `firmware/test/test_sample_pipe.c` + CMake target `sample-pipe`:
  - replays all 44 lines of `x4-t10-25min.loralog`: 41 records, exact first,
    detached, Celsius and last records, final live snapshot (805/800/807/801,
    RSSI -31, SNR 10), one learned probe count;
  - wraps malloc/calloc/realloc/free with GNU ld `--wrap` and asserts zero
    allocations across the replay;
  - asserts snapshot-before-dirty order (also on append failure);
  - full-queue test drops the ninth sample, counts it, and still lands the first
    eight records;
  - packet-counter test covers valid, malformed, foreign-ID, sync, ACK, CRC and
    last-packet age.
- Docs: design 03 §3.6 implementation notes; ADR 0029.

## Facts for later tasks

- Pipeline order is fixed: `sample_pipe_process()` stamps and queues; the
  `log_writer` appends, then `sample_pipe_complete()` publishes the snapshot and
  only then marks the UI dirty. Do not move `bridge_state_update()` into the
  sample task: the ring sequence is not known until the append.
- The log queue depth is `SAMPLE_PIPE_LOG_QUEUE_DEPTH` (8) and is static. The
  radio seam remains depth 4 (`SX4_RADIO_RX_CAPACITY` is 3 usable slots).
- A dropped sample does **not** publish a snapshot. This is deliberate: FIFO
  completions must not move live values backwards after a burst.
- `sample_pipe_counters()` aggregates `crc_failures` and `ack_attempts` from
  `sx_protocol`; valid/parse/foreign/sync/drops are owned by `sample_pipe`.
  `sx_protocol_counters_reset()` must not be called while the pipeline runs.
- `sample_pipe_esp.c` loads pairing on every accepted frame. `bridge_config`'s
  getter is an in-memory cache, so this is not flash I/O.
- UI dirty flag is an atomic bool: `ui_mark_dirty()` sets, `ui_dirty_take()`
  clears and returns. T22 should call take once per render.
- `sample_pipe_start()` is a boot step; it does not create the radio task. It
  must run after `sample_log_init`, `bridge_config_init` and `bridge_state_init`.
- T24 should take over `bridge_state_tick()` cadence; the writer currently calls
  it after every successful append, which is harmless (10-minute persistence
  window) but not the final owner.
- The host allocation assertion depends on GNU/Clang `-Wl,--wrap=...`. On Apple
  the CMake guard skips it; CI is GNU, so keep it there.
