# T20 — bridge_state: clock and live snapshot

**Date:** 2026-10-26 · **Verification:** host/CI (no board) · **Result:** done

## What landed

- `firmware/components/bridge_state/include/bridge_state.h` — public API:
  clock info, live snapshot, sample input, `core_init`, `set_time`, `tick`,
  `update`, `snapshot`, `stamp_record`, device-flag and battery setters, plus
  the `ESP_PLATFORM` boot hook.
- `firmware/components/bridge_state/bridge_state.c` — pure C11 core:
  - clock advances from an injected monotonic millisecond source; `unix_s = 0`
    means unknown;
  - `bridge_state_set_time()` rejects a time earlier than the current clock
    (`BRIDGE_STATE_ERR_TIME`), clears `estimated`, and persists the first anchor
    immediately;
  - `bridge_state_tick()` writes the `{unix_s, uptime_s}` pair at most once per
    `BRIDGE_STATE_CLOCK_PERSIST_MS` (10 min); a failed write retries after 60 s;
  - `bridge_state_stamp_record()` writes `unix_s = 0` + clears the clock-valid
    flag while unknown, and clamps to the previous record time so timestamps
    never decrease;
  - `bridge_state_update()` stores sequence, four temperatures, attached mask,
    billows state/target, RSSI/SNR without touching NVS;
  - `bridge_state_snapshot()` publishes a seqlock copy and computes `age_s`, the
    90 s `SMOKE_LIVE` bit and the clock-valid bit at read time;
  - unknown battery defaults to `BRIDGE_STATE_SOC_UNKNOWN` (255).
- `firmware/components/bridge_state/bridge_state_esp.c` — installs
  `esp_timer_get_time()`; `bridge_state_init()` is now wired in `boot.c` after
  `bridge_config_init`. Deep-sleep off-time is not known in this build.
- `firmware/components/bridge_config/` — additive anchor pair:
  `clock_uptime_s` key, `bridge_config_clock_get_full()` / `clock_set_full()`,
  migration/reset coverage. The old two-field getter/setter still work and use
  `uptime_s = 0`.
- `firmware/test/test_bridge_state.c` + `bridge-state` CTest target: 9 tests
  covering unknown-clock records, first-set persistence, 10-minute cadence with
  120 no-write samples, reboot restore (estimated), uptime-survives-wake and
  known-sleep advancement, backward-correction rejection, snapshot fields and
  90 s liveness, arguments, and factory reset of the anchor pair.
- Docs: design 03 §3.6/§3.8 notes, design 04 §4.4 note, ADR 0028.

## Gotchas for later tasks

- **Clock tick has no periodic board caller yet.** `bridge_state_tick()` must be
  called by the sample writer or the housekeeping loop. Until T24 creates the
  housekeeping task, call it from the T21 writer after appending (it only writes
  NVS when 10 minutes have elapsed).
- **Persist order inside `bridge_config_clock_set_full()` is anchor, uptime,
  valid.** The old `bridge_config_clock_set()` stores `uptime_s = 0`, so do not
  use it from bridge_state.
- **Restore is estimated, not exact.** `bridge_state_now()` reports
  `valid = true, estimated = true` after a reboot from a stored anchor. Only an
  app `set_time()` clears `estimated`. Do not treat `estimated` as unknown.
- **Backward `set_time` is refused.** T29's `set_time` must return a non-`ok`
  result (likely `invalid` or `failed`) when `bridge_state_set_time()` returns
  `BRIDGE_STATE_ERR_TIME`. The app sets time when the delta is > 2 s; the device
  may legitimately be ahead of the phone, so T29/T35 must accept the refusal
  rather than loop.
- **`tz_offset_min` is not stored.** The bridge keeps UTC; T29 ignores the field
  for device state.
- **Sequence lock is reader-safe, not multi-writer safe.** Keep snapshot and
  clock writers on their owning task (sample_pipe for updates, T29 for time,
  housekeeping for tick/setters). The T15 cache has the same single-writer rule.
- **`attached_mask` duplicates the temperature sentinels.** `bridge_state_update`
  does not re-validate; T21 must pass the parser/canonical values and keep the
  mask consistent with `TEMP_DETACHED` (T17's codec will reject a mismatch).
- **Battery default is 255/0 mV.** T24 must call `bridge_state_set_battery()`;
  the UI must render 255 as `—`, never 0%.
