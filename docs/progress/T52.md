## What landed

- **Delivery-aware control** (`app/lib/data/ble/bridge_link.dart`)
  - `BridgeControlAttempt` (`written`, `result`, `error`, `timedOut`).
  - `attemptControl()` writes one op and reports whether the GATT write
    returned. `sendControl()` is now a thin wrapper over it, so existing
    set_time/re-pair behaviour is unchanged.
- **Outcome mapping** (`app/lib/app/bridge_controller.dart`)
  - `DestructiveOutcome { success, disconnected, failed, timedOut, unavailable }`
    with `landed`.
  - `forgetPhone()` is local-first: clears the saved identity and keeps phone
    history, sends best-effort `forget_phone`, removes the OS bond on `ok` or
    the disconnect, and sets `destructiveNotice` when neither is confirmed.
  - `factoryReset()` sends `factory_reset`, accepts `ok` or the expected
    disconnect, then clears the bond/identity and returns to Setup.
  - `powerOff()` sends `power_off`, accepts `ok` or the expected disconnect, sets
    `bridgeOff` and leaves the link offline.
  - `clearBridgeHistory()` sends `clear_history`; only `ok` zeroes the Bridge
    figures. Phone history is never touched.
  - A non-`ok` result is a failure; a timeout is success only when the link is
    already gone.
- **Setup** (`setup_screen.dart`, `view_state.dart`)
  - `SetupViewState.historyOrphaned` marks `History on this phone` as history
    from the previous Bridge after forget/reset.
  - `SetupViewState.destructiveNotice` renders `Pairing not confirmed` with the
    "Bridge may still have this phone paired" explanation.
  - `hasSavedData` is kept true whenever phone readings remain.
- **Flows** (`settings_details.dart`)
  - One `confirmDestructiveAction()` helper: exact loss sheet, then a
    non-dismissible `destructive.sending` dialog until the outcome.
  - Forget/factory return to Setup; power off opens `Bridge is off`; clear shows
    `History on the Bridge cleared. New readings start a new log.`
  - Failures show one snackbar keyed `destructive.failure` and keep local state.
    Success for clear is keyed `destructive.clear.success`.
  - `ConfirmationPreviewScreen` now delegates to the same flows; no duplicated
    destructive copy.

## Facts / gotchas for later tasks

- `attemptControl().written` is the only signal that lets a disconnect count as
  success. Do not infer delivery from `sendControl()` alone.
- Forget removes the OS bond after `ok`/disconnect. Do not call `abandon()`
  before the send or the request never leaves the phone.
- `_clearSavedConnectionLocally()` is shared by forget and factory reset and
  keeps every reading on this phone. It also clears `bridgeOff`.
- Power off keeps the saved Bridge identity so a later PRG wake can reconnect;
  only `_onLinkPhase` becoming healthy clears `bridgeOff`.
- `clear_history` is the only destructive op with no expected disconnect; its
  disconnect/timeout branches are failures.
- Widget tests for outcomes use `_ScriptedController`; real op bytes and
  disconnect mapping use the `_Harness` with `FakeBridge`/`FakeBleClient`
  (plain `test`, not `testWidgets`, so real timers run).
- `pumpAndSettle` defaults to a 10-minute timeout; a hanging widget test with
  no output usually means an awaited real-async operation is stuck under fake
  time. Use `tester.runAsync` or a plain `test`.
