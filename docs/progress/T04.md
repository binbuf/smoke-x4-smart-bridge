# T04 — Firmware skeleton and partition table

## What landed

- ESP-IDF 6.0.2 project root `firmware/CMakeLists.txt` targeting `esp32s3`.
  `set(COMPONENTS main espcoredump)` before `project()` is the build whitelist;
  `espcoredump` is required by `main` so panic dumps land in the coredump
  partition. The post-build image guard is attached to
  `${CMAKE_PROJECT_NAME}.elf`.
- `firmware/main/`:
  - `main.c` — `app_main` calls `sx4_boot_run()`.
  - `boot.c` / `boot.h` — design 03 §3.4 order: NVS (fatal; erase-and-retry on
    no-free-pages/new-version), `bridge_config_init`, `board_power_init`,
    `ui_init`, `sample_log_init`, `sx_protocol_init`, `sx_radio_init`,
    `sx_radio_start`, `ble_service_start`, `ui_start`. Every non-NVS step logs
    and continues on failure. A `TODO(T20/T24)` marks the missing
    `housekeeping_start` slot.
  - `tasks.h` — X-macro task table (radio_rx, sample_pipe, log_writer, ble_tx,
    ui, housekeeping), priorities/cores from design 03 §3.3. Declared total
    22,528 B; budget 24 KiB; `_Static_assert` on total, budget, row count.
  - `tasks.c` — materialises `sx4_tasks[]` from the same list.
  - `CMakeLists.txt` — `REQUIRES` the eight component stubs plus `nvs_flash`.
- Component stubs, one header + one `.c` each, all returning `ESP_OK`:
  `sx_protocol`, `sx_radio`, `sample_log`, `bridge_config`, `bridge_state`,
  `ble_service`, `ui`, `board`. `sample_log/include/log_io.h` from T03 is
  unchanged; the new API is `sample_log.h`.
- `firmware/partitions.csv` — no-OTA layout: `nvs` 24K @0x9000, `phy_init` 4K
  @0x11000, `coredump` 56K @0x12000, `factory` app 2M @0x20000, `samples`
  data/0x40 6016K @0x220000. Fills 8 MiB exactly; no OTA slot.
- `firmware/sdkconfig.defaults` — target `esp32s3`, custom partition table,
  coredump-to-flash (ELF, CRC32), network components documented as off.
  `firmware/sdkconfig.defaults.heltec-v3` — 8 MiB flash, 240 MHz.
- `firmware/tools/check_image.py` — post-build guard: target, forbidden
  component set (Wi-Fi/IP/HTTP/OTA update stack), and no OTA partition rows.
  Wired into `firmware/CMakeLists.txt`; also runnable by hand.
- `firmware/test/test_tasks.c` + `task-budget` CTest — verifies table/macro
  agreement, row names, per-task minimum, core pinning and 2 KiB headroom.
- ADR `0015-firmware-build-boundary.md`; design 03 §3.3 and §3.13 updated.

## Gotchas for later tasks

- **IDF environment on this bench:** the default `idf6.0_py3.12_env` has
  esp-idf-monitor 1.9.0 and fails `export.ps1`. Use
  `IDF_PYTHON_ENV_PATH=C:\Users\dan\.espressif\python_env\idf6.0_py3.13_env`
  before `D:\esp\esp-idf\export.ps1`. `idf.py --version` prints v1.0.3 (the
  idf.py tool version, not the IDF version); IDF is 6.0.2.
- **Always build from `firmware/`** (`idf.py -B build ...`) so `build/` and
  `sdkconfig` land under `firmware/`; a root-relative `-B build` pollutes the
  repo-root `build/`.
- **Build whitelist:** `set(COMPONENTS main espcoredump)` is deliberate.
  Adding a source file needs no change, but adding an IDF component requires
  adding it to `COMPONENTS` (or as `REQUIRES` of main) and keeping
  `check_image.py` green.
- **`app_update` is baseline:** `esp_partition` privately requires it and links
  only `esp_ota_get_running_partition` (~188 B). It is allowed by the guard.
  The no-OTA guarantee is no OTA slot + no update component.
- **`bt` requires `esp_wifi` in IDF 6:** adding `bt` to `COMPONENTS` pulls in
  `esp_wifi`, `wpa_supplicant`, `esp_netif` and `lwip`, and the guard fails.
  This is the open T27/T30 conflict; do not weaken the guard without an ADR
  update. T04 therefore does not link NimBLE yet.
- **sdkconfig symbols for excluded components do not exist.** With the
  whitelist, `CONFIG_BT_*`, `CONFIG_ESP_WIFI_*`, `CONFIG_LWIP_*` are absent even
  if written in `sdkconfig.defaults`; they only take effect once the component
  is in the build. `sdkconfig` and `sdkconfig.old` are generated/ignored.
- **Partition CSV subtype:** `data,custom` is not a keyword in IDF 6's parser.
  `samples` uses numeric subtype `0x40`; it decodes as `64` in the generated CSV.
  Edit `partitions.csv`, not the generated table.
- **Coredump settings** (`CONFIG_ESP_COREDUMP_ENABLE_TO_FLASH`, ELF/CRC32) are on;
  `espcoredump` is linked and the 56K partition fits. Retrieval over USB is
  still TODO.
- **Do not replace** `firmware/components/sample_log/include/log_io.h`; it is
  the T03 host seam. The stub `sample_log_init` in `sample_log.c` will be
  replaced by T19.
- `firmware/build/` is ignored by the root `build/` rule; `sdkconfig.defaults*`
  are tracked.
