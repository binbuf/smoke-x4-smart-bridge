# T47 — ble_service: config read/write and stats read

**Date:** 2026-10-27 · **Verification:** H (host) · **Result:** done for the
firmware/host half; the real-phone/OLED bench check is deferred to T51/T55 as
the task's design note allows.

## What landed

- `firmware/components/ble_service/ble_config.c` + `include/ble_config.h`
  - Pure validator/encoder for the 80-byte `config` payload.
  - `ble_config_parse()` accepts only one complete 80-byte struct: `ver = 1`,
    units 0/1, timeout 0/30/60/120, a 1–15-byte UTF-8 name NUL-terminated in
    its 16-byte field. Reserved target and bytes 23–79 are ignored.
  - Nonzero `billows_mode` returns `BLE_CONFIG_UNSUPPORTED` before any other
    field check; all other malformed bodies return `BLE_CONFIG_INVALID`.
  - `ble_config_encode()` always writes `ver = 1`, target/mode 0 and zeroes the
    57 reserved bytes.
- `firmware/components/ble_service/ble_stats.c` + `include/ble_stats.h`
  - Pure 60-byte encoder plus `ble_stats_build_flags()`; bit 7 is masked off.
- `firmware/components/ble_service/ble_service.c`
  - `config` read rebuilds the struct from `bridge_config_get_device()`; write
    accepts exactly 80 B (`ble_hs_mbuf_to_flat` after NimBLE reassembles queued
    writes), validates, persists with one `bridge_config_set_device()`, then
    calls the config-applied seam.
  - `stats` read builds one fresh view: one `sample_log_get_info()` extent,
    min/max record times, live flags/counters/battery/heap/drops.
  - Refusals use ATT application errors `0x81` invalid / `0x82` unsupported /
    `0x87` storage (see ADR 0051).
- `bridge_state` gained `dropped_samples` (live snapshot field +
  `bridge_state_set_dropped_samples()`); `sample_pipe_esp.c` publishes the
  counter after each packet batch.
- UI runtime apply: `ui_snapshot_t.units` now drives °F/°C rendering (stored
  values stay °F); `build_snapshot()` reads units from `bridge_config`; boot.c
  registers `ble_service_set_config_applied_callback()` to call
  `ui_set_display_timeout()` and `ui_mark_dirty()`.
- Tests: `firmware/test/test_ble_config.c` (min/max name, four timeouts, both
  units, reserved ignored, bad length/version/UTF-8/units/timeout, control-mode
  refusal, MTU-23 reassembly); `firmware/test/test_ble_stats.c` (empty log,
  full ring, flags, sentinels, capacity, signed RSSI/SNR, unknown battery,
  reserved bytes, MTU-23 reassembly); `test_ui_render.c` adds °C conversion.
- Docs: 05 §5.9/§5.10 implementation rules, ADR 0051.

## Facts / gotchas for later tasks

- `ble_config_parse()` treats `billows_mode != 0` as `unsupported` and checks
  it after length/version, before units/timeout/name. Keep that order: the
  acceptance vector expects a named control refusal even if other reserved
  bytes are garbage.
- `device_name` must be 1–15 bytes, not merely NUL-terminated: the NVS layer
  rejects an empty name. Do not relax this in the BLE validator.
- Config writes are full-struct only. NimBLE gives the callback the
  reassembled mbuf for Prepare/Execute writes; there is no device-side merge.
- `config` is authenticated, `stats` only encrypted. `stats` has no write path;
  NimBLE rejects a write from the characteristic flags.
- `records_stored` is the live record count (not the seq span). Capacity is
  `info.sector_count * 225` and is 338,400 for the shipped partition.
- Oldest/newest are read from the min/max records after the extent snapshot;
  either is 0 when the clock was unknown at record time.
- The UI reads `units` from `bridge_config` on each snapshot, so after a write
  `ui_mark_dirty()` is enough; the timeout needs the explicit
  `ui_set_display_timeout()` call in boot.c's config-applied handler.
- `ble_service` must not depend on `ui` (ui already depends on ble_service);
  use the config-applied callback seam for UI effects.
