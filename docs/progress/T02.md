# T02 — Protocol contract and codegen

## What landed

- `protocol/records.yaml`: sample_rec (18 B), sector_header (16 B), temperature
  sentinels, record flags, log constants (sector/ring geometry, sample cadence,
  version) and CRC-16/CCITT-FALSE parameters.
- `protocol/ble.yaml`: service UUID, all 8 characteristic slots with
  properties/security/payload, payload layouts (info, live, control envelope +
  op bodies, result, sync_ctrl, sync frame/START/END, config, stats, adv_status),
  7 control ops, 8 result statuses, flags (live/caps/stats/sync_frame), and
  enums (sync cmd/direction/status, units, billows mode).
- `tools/protogen/protogen.py`: deterministic YAML→C/Dart generator. No
  timestamps, YAML order is emission order, LF-only output. It validates layout
  sizes and CRC ranges before writing.
- `protocol/gen/records.h`, `records.c`, `records.dart`: committed output with
  structs, constants, flag masks/accessors, enums, encode/decode functions,
  CRC-16/CCITT-FALSE, and the u24 sequence codec.
- `make protocol` regenerates; `make protocol-check` is the byte-for-byte drift
  check; `make protocol-test` compiles/runs the C codec test and runs the Dart
  codec test.
- `protocol/test/test_records.c` and `protocol/test/records_test.dart`: both
  decode and re-encode the normative `live` vector from design 05 §5.4, plus
  record CRC rejection, u24, CRC check vector, result framing, sync payloads,
  and info strings.
- ADR `docs/design/adr/0013-generated-protocol-codecs.md`; codegen notes added
  to design 04 §4.2 and 05 §5.1.

## Key facts for later tasks

- Generated symbols use the `SX4_` prefix in C and lowerCamel in Dart. Layout
  key `sample_rec` → `sx4_sample_rec_t` / `SampleRec`; `live` → `sx4_live_t` /
  `Live`; `sync_ctrl` → `sx4_sync_ctrl_t` / `SyncCtrl`.
- Every generator function returns the encoded byte count; C `encode` returns
  `0` when the output buffer is too small. C `decode` verifies CRC fields and
  returns `false` (struct may be partially filled only on length failure).
- `u24` C struct fields are stored as `uint8_t[3]` to keep the packed size. Use
  `sx4_<layout>_<field>_get/set()` (e.g. `sx4_sample_rec_seq_set`). Dart uses a
  plain `int` with `seq24Read` / `seq24Write`.
- `result` is the only variable-length layout: C struct is max-size 64 B and
  `sx4_result_encode` returns `5 + len`; Dart `Result.encode()` returns the
  actual bytes and computes `len` from `detail`.
- BLE UUIDs are derived from `ble.yaml`'s base UUID: `XXXX` is replaced by the
  characteristic slot (`0001`…`0008`). Do not hard-code a second copy.
- The design says `info.fw` is 12 B, `model` 8 B, and `device_id` 4 B; the YAML
  matches. `config` is 80 B with 57 reserved bytes.
- `protocol/gen/` must stay committed. Never add it to `.gitignore`.

## Verification run

```text
make protocol-check
# protocol/gen is current

make protocol-test CC=gcc DART=<dart>
# gcc -std=c11 -Wall -Wextra -Werror ... -> build/protocol_test.exe
# build/protocol_test.exe -> exit 0 (assert-based C tests)
# Dart protocol codec tests passed

dart analyze protocol/gen/records.dart protocol/test/records_test.dart
# No issues found!

# drift probe: append a comment to records.h
make protocol-check        # stale: protocol/gen/records.h; exit non-zero
make protocol              # restores
make protocol-check        # current
```

On this bench `gcc` is at `C:\msys64\ucrt64\bin\gcc.exe`; make's shell only
finds it after `PATH` includes that directory. The Flutter `dart` shim in
`D:\flutter\bin` is not executable under the MSYS bash that `make` uses; pass
`DART=D:/flutter/bin/cache/dart-sdk/bin/dart.exe` when running from this shell.
CI (T08) should use the normal `gcc`/`dart` on PATH.
