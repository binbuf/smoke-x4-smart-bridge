## Facts / gotchas for later tasks

- **T44:** `historyRevision` is bumped only by sync. After `deleteRange`, bump it
  (or rebuild History) or the screen keeps the pre-delete read model.
- **Chart gaps are pre-split.** `HistoryArchive` decimates with the source
  tolerance and marks a `decimated` fixture; the painter must use
  `HistoryFixture.decimated` (already wired) and not reapply 90 s to bucket
  spacing. Fixture/demo series stay non-decimated and keep the 90 s rule.
- **Summary is SQL, not the chart.** Never compute Min/Max from decimated points;
  use `probeStatsInRange`. `HistoryProbeStatsRow` values are already °F.
- **Bucket width:** `maxRawRows = 4000`, about 1,200 SQL buckets, then LTTB 800
  per series. Zooming a very long range cannot reveal detail below the bucket
  width; re-query on zoom only if the product asks.
- **Cook detection:** 5-minute buckets, split at >30 min idle, drop cooks under
  10 min. `hasGap` means a device gap overlap or an internal hole >10 min.
  `In progress` is the latest cook whose end is within 15 min of `content.now`.
- **Async History:** any code that needs History data must use
  `controller.loadHistoryView()` when `sampleDao != null`; `historyViewFor` is
  the synchronous fixture path only.
- **Tests:** use `sampleDao: null` for demo/fixture widget tests. The archive
  widget test uses a small read-only `SampleDao` fake; do not drive sqflite FFI
  from `pumpAndSettle` (it can hang the fake-async zone).
- **SQLite division:** `GROUP BY CAST(recorded_ms / ? AS INTEGER)` relies on
  integer division; keep `bucketMs` an integer.
