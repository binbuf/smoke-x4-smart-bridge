## What landed

- **Firmware decode:** `sx_protocol.c` sets `billows_target_deg` from probe 4
  `max` and `billows_target_valid = true` while `billows_attached` (T56:
  `max` = base set temp; `min` = 0). Detached frames keep `valid = false`, so
  the X4's `160`/`32` fallback never becomes a target.
- **Pipeline:** `sample_pipe.c` converts a valid target to canonical °F tenths,
  including °C packets (`F10 = C × 18 + 320`). `ble_live` still encodes `0` for
  an invalid target; `billows_output` is cleared on the wire.
- **Caps/control:** `caps.billows_observe = 1`, `caps.billows_control = 0`,
  `set_billows_target` returns `unsupported`, and config Billows keys remain
  unwritten. The single `LoRaSend(` call site is still the pairing ACK.
- **App:** real `billowsLastDetectedAt`/`billowsLostAt` tracking from `live`
  replaces the hardcoded 12-minute age. `Last detected`, the lost notice and the
  connection log now age from the actual event. Settings → Bridge → Billows
  uses `Set temp (last known)` offline and shows the Billows-filtered connection
  log. No mode switch, target editor, Set target action or fan claim exists.
- **Tests:** T56 capture replay in `sx-protocol` (225/250/275 only attached,
  detached defaults rejected); known/unknown/°C target in `sample-pipe`; new
  `app/test/billows_observation_test.dart` for known, unknown, offline, lost and
  no-send-path; existing widget tests cover the absent card and single notice.

## Gotchas for T59

- The target is only valid while `billows_attached` is set. A detached frame
  carries `max=160`, `min=32`; the parser deliberately returns no target.
- `Last detected` and the loss event now use the phone receipt time of the last
  attached state packet, not the last X4 packet. An X4 that keeps sending after
  detach does not keep the age artificially fresh.
- All target values on the wire are whole degrees in the packet's active unit;
  the bridge stores °F tenths. The real °C flip is still a T59 check.
- The app review shell still seeds Billows/225 °F for screenshots; a real launch
  clears it and renders only `live` data.
