# T40 — app local database and DAO

## What landed

- `app/lib/data/db/app_database.dart`
  - schema version bumped `1` → `2`; version 1 was the empty T05 open path.
  - `onCreate` / `onUpgrade` share one forward-only migration list.
  - tables exactly as 04 §4.7: `bridge`, `sample` (+ `sample_time` index), `gap`.
  - `openInMemory(factory: databaseFactoryFfi)` is the host-test database.
- `app/lib/data/db/sample_dao.dart`
  - `SampleDao` interface + `SqfliteSampleDao` single implementation.
  - rows/models: `SavedBridge`, `DeviceSample`, `StoredSample`, `StoredGap`,
    `SampleExtent`, `HistoryDeletion`.
  - `insertBatch` / `insertSamples`: one transaction per batch, `INSERT OR
    IGNORE` by `(bridge_id, generation, seq)`. A later exact-clock record
    upgrades an estimated row; a worse duplicate never replaces an existing row.
  - unknown clock: `unix_s = NULL`, `time_estimated = 1`, and
    `recorded_ms = syncWallMs - (deviceMaxSeq - seq) * 30000`.
  - temperature sentinels `-32768` / `-32767` and absent probes become `NULL`.
  - `samplesInRange` (half-open `[fromMs, toMs)`), `newestSamples`,
    `countSamples`, `extent` (min/max seq + min/max `recorded_ms` + count),
    `gaps`, `insertGaps`.
  - `deleteRange` returns `samplesDeleted`, `gapsDeleted`, `gapsTrimmed`,
    `gapsAffected`; it removes gaps detected in the window and trims/removes
    gaps overlapping the deleted sequence extent.
  - saved-connection queries: `savedBridge()` (latest `last_seen_ms`),
    `bridgeById`, `saveBridge`, `touchBridge`, `removeBridge`,
    `removeAllBridges`.
- `app/test/local_database_test.dart`: 11 tests covering schema, 10,000-row
  insert/range/count/extent/delete, duplicate idempotency, exact-over-estimated
  upgrade, unknown-clock mapping, bridge ordering/touch, forget keeps orphaned
  history, gap trim/remove, file relaunch, and v1→v2 migration.
- `app/test/app_skeleton_test.dart`: the old “schema not landed yet” test now
  inserts into the real `sample` table.
- Docs: 04 §4.7 and 06 §6.2 implementation notes; ADR 0045.

## Facts / gotchas for later tasks

- **T41:** call `dao.insertBatch(...)` with `syncWallMs` (phone receive time) and
  `deviceMaxSeq` from the sync START/END snapshot. Keep old generations; the PK
  includes `generation`, so generation changes are not deletes.
- A new batch must be committed before advancing `bridge.cursorAfter`; there is
  no DAO transaction spanning samples + cursor yet. If T41 needs atomic
  sample+cursor writes, add one DAO method rather than touching the tables
  directly (out of T40 scope).
- `insertSamples` returns only newly inserted row count. Upgrading an estimated
  row to exact does not change that count.
- Deletion range is half-open: `recorded_ms >= fromMs AND recorded_ms < toMs`.
  For “delete everything” use `0 .. 0x7FFFFFFFFFFFFFFF`.
- Gap rows have no time column. `deleteRange` uses `detected_ms` for gaps
  detected inside the window and additionally trims by deleted sequence extent.
- `SavedBridge.copyWith` cannot clear nullable fields; construct a new row when
  cursors must become `NULL`.
- The schema deliberately has no foreign keys: forgetting the Bridge must leave
  orphaned `sample`/`gap` rows readable.
- `ON CONFLICT ... DO UPDATE` was avoided for Android system SQLite
  compatibility; use the same `INSERT OR IGNORE` + conditional `UPDATE` pattern
  for future portable writes.
- `SqfliteSampleDao.close()` closes the `AppDatabase` it was given.

## Follow-ups

- **T41:** add an atomic “insert batch + advance cursors” DAO method if the
  repository needs crash-consistent cursor advancement. Cursor fields already
  exist on `SavedBridge`.
- **T42:** use `samplesInRange` + `extent` and add SQL bucketing/decimation
  helpers; the DAO intentionally returns rows, not chart points.
- **T44:** use `HistoryDeletion.gapsAffected` in the confirmation copy and
  `deleteRange` for 30/90 days/all. No automatic deletion.
- **T43:** `savedBridge()` on launch, `touchBridge()` on every successful
  connect, `removeBridge()`/`removeAllBridges()` only after confirmation.
- Optional future: a `WITHOUT ROWID` or covering index pass if the full
  338,400-row ring query plan shows table scans; current index covers
  `(bridge_id, recorded_ms)`.
