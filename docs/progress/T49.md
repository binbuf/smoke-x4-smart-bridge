# T49 — ble_service: destructive-action state and reconnect

**Date:** 2026-10-27 · **Verification:** H + firmware build · **Result:** done
for the host/firmware half. The destructive board walk (forget re-advertise,
factory reboot, power-off sleep) is deferred to T55 by the task's bench-safety
note; every state transition is host-tested and the T49 image is built/hashed.

## What landed

- `firmware/components/ble_service/ble_destructive.c` + `include/ble_destructive.h`
  - Pure link/action state machine: idle → answered → running → complete /
    reboot / sleep, with the pending action and advertising flag.
  - Invariant `ble_destructive_consistent()`: never advertising while the link
    is up; a owed reboot/sleep never advertises.
  - Link drop after `result ok` keeps the pending action (the timer is not
    cancelled): forget/clear/unpair re-advertise, factory/power stay silent.
  - Failed late action returns to discovery when the link is down so the app can
    retry without rewriting the already-sent `result ok`.
  - `ble_destructive_boot_plan(clear_pending)`: normal vs
    clear-then-advertise.
- `ble_service.c`
  - Drives the new state machine on result, GAP connect/disconnect, action
    timer completion and host reset/stop.
  - Forget captures the peer identity at write time; a deferred forget with the
    app already gone removes that bond and leaves other bonds intact. The link
    is terminated only when it is still the same peer.
  - New `ble_service_prepare_sleep()` stops advertising, cancels advertising
    timers and clears the passkey before deep sleep, without deinitialising
    NimBLE (safe from the BLE action timer).
- `boot.c`: power off calls `ble_service_prepare_sleep()` before
  `board_enter_deep_sleep()`.
- New `firmware/test/test_ble_destructive.c` (`ble-destructive`), linking the
  real router/dispatcher, advertising machine, factory-reset step table and
  boot-time log clear with fake BLE/NVS/board backends:
  - result-then-disconnect ordering, one teardown;
  - forget re-advertise (current bond gone, other remains);
  - factory wipe-and-reboot (never advertises in between);
  - power-off sleep (silent);
  - normal disconnect re-advertise;
  - app drop mid-op for all five destructive actions;
  - power cut with `clear_pending` set: reopen finishes the erase, count 0,
    new generation, flag cleared, only then advertise; and the reset step table
    writes generation + `clear_pending` before any erase.
- Docs: 05 §5.12 implementation rules (T49), 03 §3.5.2 note, ADR 0053.

## Deviations

- No production change was needed for the normal disconnect path (T36 already
  re-advertises); the new state machine now gates it so a pending factory/power
  op does not briefly advertise before reboot/sleep.
- The board walk is not run here, per the bench-safety note. T55 must flash the
  T49 image with an NVS/samples backup and a re-pair plan.
- The 50 ms factory reboot timer remains in `boot.c`; its ordering is unchanged
  (wipe fully completes before the reboot is armed).

## Facts / gotchas for later tasks

- `ble_destructive.c` is the single place that decides advertise/reboot/sleep;
  keep its switch in step with any new `ble_control_action_t`.
- `ble_service_prepare_sleep()` must stay NimBLE-deinit-free: it runs on the BLE
  action timer, and `ble_service_stop()` deletes that same timer.
- Forget now prefers the peer captured at write time over the live link. This is
  deliberate: a different phone may connect inside the 250 ms window.
- The factory power cut is covered by `clear_pending`, not a separate reset
  marker: config keys are independently readable with defaults, the log is
  fully erased on boot, and advertising starts only after the erase completes.
- Inline `$env:IDF_PYTHON_ENV_PATH=...` gets mangled by the shell harness; put
  the ESP-IDF export and `idf.py` call in a `.ps1` file.
