## What landed

- `firmware/components/ble_service/include/ble_live.h`, `ble_live.c` — pure C11
  `live` encoder for the fixed 20 B payload:
  - maps one `bridge_state_live_t` to the generated `sx4_live_t`, so offsets and
    little-endian layout stay in `protocol/gen/records.c`;
  - detached probes are forced to `SX4_TEMP_DETACHED` even if the snapshot temp
    field carries a value;
  - `seq = SX4_SEQ_NONE` until the log stored a sample (a real first sequence of
    0 is preserved via the new `have_seq`);
  - invalid Billows target → 0; reserved `billows_output` is always cleared.
- `bridge_state` gained `have_seq` on the sample and live snapshot and an
  optional `bridge_state_set_change_hook()`. The hook fires after
  `bridge_state_update()`, after an actual flag transition in
  `bridge_state_set_*()`, and after a successful `set_time()`, outside the
  seqlock.
- `firmware/components/ble_service/include/ble_tx.h`, `ble_tx_core.c` — pure
  bounded ring (8 frames) owned by `ble_tx`:
  - stores already-encoded 20 B payloads;
  - dedupes on wire `seq` + `flags`, so one frame per stored sample and one per
    flag transition, and no frame for an unchanged snapshot;
  - a full ring drops the newest frame and increments `dropped` (sync recovers).
- `firmware/components/ble_service/ble_tx.c` — the single writer task:
  - `ble_tx_start()` creates the task and installs the bridge_state hook;
  - producers only snapshot + append under a short portMUX critical section;
  - the task drains the ring and calls `ble_gatts_notify_custom()` for `live`;
  - a 1 s timeout catches time-driven transitions such as `smoke_live` expiry;
  - subscribe clears stale frames and primes the queue with the current
    snapshot; disconnect/subscription-off clear the queue.
- `ble_service.c`:
  - `live` read now encodes the current `bridge_state_snapshot()` (read
    fallback), replacing the T27 zero placeholder;
  - GAP CONNECT/DISCONNECT/SUBSCRIBE feed `ble_tx`; the CCCD-
    encrypted property and `READ_ENC` are unchanged (NimBLE still auto-adds
    `0x2902` on the Notify characteristic);
  - `ble_tx_set_live_handle()` is called after service registration.
- `firmware/main/boot.c` starts `ble_tx` before `ble_service`.
- `firmware/test/test_ble_live.c` + `ble-live` CTest (18 suites total):
  - exact 05 §5.4 vector;
  - four attached, one detached, all detached, clock invalid, Billows attached;
  - `0xFFFFFFFF` no-sample sentinel vs a real seq 0; reserved output bit;
  - encoder argument checks;
  - eight stored samples → eight ordered frames, and the frame bytes equal the
    read-fallback encoder output for the same snapshot;
  - every non-reserved flag toggle queues one frame; an unchanged snapshot and
    the reserved bit do not;
  - bounded queue drop and clear semantics.
- `test_bridge_state.c` gained a hook test (sample publication, real flag
  transition, successful set_time, unregister).

## Deviations / decisions

- `have_seq` was added to `bridge_state_sample_t`/`bridge_state_live_t` because
  the ring's first stored sequence is legitimately 0, so `seq == 0` cannot mean
  "none". ADR 0035 records this.
- Flag notifications are fired from a `bridge_state` observer rather than from
  every caller (sample_pipe/UI/housekeeping/T29). This keeps all current and
  future `bridge_state_set_*()` calls covered. The hook must stay non-blocking.
- The `ble_tx` task polls once per second in addition to the queue wake-up, to
  catch clock-driven `smoke_live` expiry (no setter runs at that transition).
- Battery changes alone do not notify: they do not change `seq` or a flag; the
  read fallback and sync carry them. This matches the task's notification
  policy.

## Gotchas for later tasks

- **Producers must set `have_seq`.** `sample_pipe` sets it only when the log
  assigned the sequence; T31 sync/read code should treat `have_seq == false` as
  `0xFFFFFFFF`, not `seq == 0`.
- **Do not call NimBLE from the sample path.** Keep `ble_tx_live_changed()` as
  the only fan-in; it only appends to the ring.
- **`ble_tx_start()` must run before `ble_service_start()`** (boot.c already
  does this); the live value handle is registered later by `ble_service_start`.
- **Raising the queue depth** changes stack/heap only in `ble_tx_core_t` (static,
  8 × 20 B). The task row already exists in `firmware/main/tasks.h`; do not add
  a second BLE writer task.
- **CCCD:** T30 must keep `BLE_GATT_CHR_F_NOTIFY_INDICATE_ENC` on `live`.
  NimBLE auto-adds `0x2902`; there is no custom descriptor callback.
- **T29:** `set_time` now fires the change hook automatically; do not add a
  second live notification call. `control`/`result` remain separate slots.
- **T31:** a missed live frame is recovered by sync; do not try to replay the
  `ble_tx` ring. Clear/replace the ring only on subscribe/disconnect as T28
  does.
