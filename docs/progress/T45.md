## Deviations / decisions

- **Whole-range empty action:** the 06 §6.8 “No history in range” row is the
  probe-specific case (`Probe 3…` / `Show all probes`). A window that contains
  no readings for any probe keeps T42's `Show all saved history`; `Show all
  probes` cannot recover an empty range. Documented in ADR 0050.
- **Protocol mismatch:** already implemented as the Setup-owned page (T33);
  T45 added matrix coverage and copy assertions rather than duplicating it on
  Live. A launch-time mismatch on a saved Bridge still resolves to the
  cached/offline path; see follow-ups.
- **No-X4 surface:** kept the existing inline notice for an unpaired X4 and the
  amber X4-node dialog for paired/lost; both now use the approved no-data copy.

## Facts / gotchas for later tasks

- `LiveViewState.telemetryStatusLabel` is the single source for
  `Showing saved readings · last reading …`; do not hand-build that string.
- `ConnectionBanner` (History) renders `connectionTitle` + `connectionSubtitle`.
  A failure with cache now has the saved-readings title, so `Can’t reach the
  Bridge` only appears when `offlineCache == false`.
- The no-cache notice deliberately excludes `probePresence == none` from the
  separate no-probes notice; otherwise the user sees two failure surfaces.
- `_EmptyHistoryContent` / `_ProbeGapContent` in the matrix test are the quickest
  way to make a no-data History state without sqflite.
- Do not compute Summary totals from the chart; the existing SQL stats path is
  still the only source. A probe with no rows stays `No data` with dashes.
- `Find.byType(HistoryChart)` is the check for “a chart frame really rendered”;
  the empty states use `EmptyState` instead.
