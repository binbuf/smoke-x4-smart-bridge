# T30 — ble_service: security, passkey, and advertising

**Date:** 2026-10-27 · **Verification:** host/CI + firmware compile · **Result:** done
**Board:** the real-phone bond, wrong-code, reboot and fifth-phone checks are
deferred to T37 per the task's Done-when; the host vectors/transitions and the
image guard are the gate now.

## What landed

- `firmware/components/ble_service/include/ble_adv.h`, `ble_adv.c` — pure C11
  advertising core:
  - 9-byte scan-response blob (`ver`, `flags`, P4 `pit_temp_f10`,
    `battery_pct`, `billows_target_f10`, `age_s` clamped 0–255, reserved 0);
  - `SmokeX4-XXXX` from the last two BLE MAC bytes, uppercase hex;
  - 21-byte advertising PDU: Flags (`0x06`) + complete 128-bit service UUID;
  - 27-byte scan response: complete local name + manufacturer block with
    company ID `0xFFFF`;
  - interval state machine: boot/disconnect/failed connect open a fresh
    250 ms window for 60 s, the deadline returns 1,000 ms, an advertising
    timeout restarts without extending the window, connect/stop turn it off;
  - `ble_adv_interval_units()` maps ms to NimBLE 0.625 ms units.
- `firmware/components/ble_service/include/ble_security.h`, `ble_security.c` —
  pure C11 bond/passkey rules:
  - 4-bond cap, `can_bond()` false at 4 and no eviction;
  - fresh six-digit code per attempt, 60 s lifetime, cancel on bond end,
    millisecond-wrap-safe expiry.
- `firmware/components/ble_service/ble_service.c` — NimBLE glue:
  - `DisplayOnly` + bonding + MITM + SC-only; a non-`DISP` passkey action and
    an unauthenticated encryption change both terminate the link (no Just Works
    downgrade);
  - `BLE_GAP_EVENT_PASSKEY_ACTION/DISP` generates the code with `esp_random()`,
    injects it through `ble_sm_inject_io()` and shows it via the UI callback;
  - advertising starts on host sync, restarts on disconnect/failed connect and
    on `ADV_COMPLETE`; restarts are deferred 10 ms so `ble_gap_adv_start()` is
    never called inside a GAP callback; its own stop is flagged so it is not
    treated as a timeout;
  - passkey expiry and the tap-to-cancel API terminate the link and clear the
    overlay;
  - `store_status_cb` stays NULL so a full store aborts the new bond instead of
    evicting the oldest phone; repeat pairing removes only the phone asking;
  - `ble_service_bond_count()` cached on sync/encryption/pairing events;
    disconnect clears `live.flags.sync_active`.
- `firmware/components/ble_service/include/ble_service.h` — passkey-display
  callback seam, `ble_service_bond_count()`, `ble_service_cancel_pairing()`.
- `firmware/main/boot.c` — wires the passkey callback to `ui_set_passkey()`.
- `firmware/components/ui/ui.c` — connection page now shows the real link state
  and bond count; a tap on the passkey overlay cancels the attempt.
- `firmware/test/test_ble_adv.c` + `ble-adv` CTest — exact PDU/scan-response/
  blob vectors, name formatting, interval units, every advertising transition,
  bond cap and passkey format/lifetime.
- Docs: design 05 §5.2 implementation rules; ADR 0037.

## Deviations / decisions

- **No UI dependency cycle:** the passkey overlay is reached through
  `ble_service_set_passkey_callback()` installed in `boot.c`, not by including
  `ui.h` from `ble_service` (ui already depends on ble_service).
- **Expiry and tap terminate the link**, not just hide the code. This makes the
  "code expires" rule meaningful and gives the phone a failed-bond signal.
- **`sm_sc_only = 1`** was added on top of `sm_sc`/`sm_mitm` so a legacy
  (non-SC) phone is refused rather than downgraded.
- **Status blob is rebuilt on each advertising start**, not every sample. A
  scanner sees fresh values after boot/disconnect/interval change; live
  telemetry already comes from the encrypted `live` characteristic.
- **Advertising duration is `BLE_HS_FOREVER`**, but `ADV_COMPLETE` is still
  handled (timeout restart) in case the controller ends the procedure.
- `ble_service_bond_count()` is cached for the UI instead of reading the
  NimBLE store from the UI task; `info.bonds_free` still counts the store on
  every read.

## Gotchas for later tasks

- **T37:** bond with the OLED code, reject a wrong code, reboot and reconnect
  without a prompt, read `info` before bonding, confirm `live` returns 0x0F
  before encryption, scan at boot/disconnect and observe 250 ms → 1,000 ms,
  then fill all four slots and confirm the fifth bond fails.
- **T33:** the app must show "look at the Bridge screen" before the OS bond
  prompt. Firmware refuses non-passkey pairing; there is no Just Works path.
- **NimBLE names:** the event is `BLE_GAP_EVENT_PARING_COMPLETE` (typo is in
  the stack) and its union member is `pairing_complete` (no `authenticated`
  field; query `ble_gap_conn_find()` for the security state).
- **Advertising data:** `ble_gap_adv_set_data()`/`ble_gap_adv_rsp_set_data()`
  return `EBUSY` while advertising; stop first. Calling `ble_gap_adv_stop()`
  emits `ADV_COMPLETE`; `s_adv_stopping` filters that from a real timeout.
- **Event listener:** keep passing `NULL` as the `ble_gap_adv_start()` callback;
  the registered listener receives connect/advertising events, and passing the
  same function would double-handle them.
- **T31:** `sync_active` is only cleared by T30 on disconnect/connect; the sync
  owner must set it true/false around a transfer.
- **T48:** after `forget_phone`/factory reset the bond count cache must be
  refreshed (call the same refresh path or `ble_service_bond_count()` may be
  one event stale until the next encryption/pairing).
