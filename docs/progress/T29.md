# T29 — ble_service: control, result, and the clock

**Date:** 2026-10-27 · **Verification:** host/CI + firmware compile · **Result:** done
**Board:** the real write/notify round trip and the ATT security rejection are
deferred to T37/T30; the byte-level dispatcher, clock update and image guard are
the gate now.

## What landed

- `firmware/components/ble_service/include/ble_control.h`, `ble_control.c` —
  pure C11, allocation-free `control` dispatcher and `result` encoder:
  - parses `ver, op, op_id, body…`, echoes the app's `op_id` unchanged;
  - validates the exact body size for every known op before acting
    (`set_time` 10 B, `set_billows_target` 2 B, ops 2/3/4/5/7 0 B);
  - `set_time` converts `unix_ms / 1000` and calls `bridge_state_set_time()`;
    the bridge keeps UTC and ignores `tz_offset_min`; zero/backward time is
    `invalid` "clock out of range";
  - unknown ops → `unsupported`; ops 2/3/4/5/7 → `unsupported` until T48
    registers an action handler (then `ok` + `action` + 250 ms);
    `set_billows_target` → `unsupported` always;
  - result encoder: `ver, op, op_id, status, len, detail[len]`, 5..64 B,
    detail capped at 59 B and never split inside a UTF-8 sequence;
  - `ble_control_status_detail()` gives human text for every status 0–7;
  - `ble_control_write_security()` returns the named ATT values (0x0F
    unencrypted, 0x05 unauthenticated);
  - reply-first seam: `result.action` + `action_delay_ms` and
    `ble_control_set_action_handler()`/`ble_control_run_action()` for T48.
- `firmware/components/ble_service/ble_service.c`:
  - the `control` write path now copies up to 64 B, dispatches, encodes and
    notifies `result`, split at `MTU−3` (first chunk carries the header);
  - tracks the `result` CCCD subscription independently of `live`;
  - arms a one-shot `esp_timer` (default `BLE_CONTROL_ACTION_DELAY_MS` = 250 ms)
    only after the result is handed off; no action runs in T29;
  - the security check now routes authenticated slots through
    `ble_control_write_security()`, with static asserts against NimBLE's
    `BLE_ATT_ERR_*` values;
  - `ble_service_stop()` deletes the action timer.
- `firmware/test/test_ble_control.c` + `ble-control` CTest:
  - `set_time` round trip against the real bridge_state clock (same `op_id`,
    `op = 1`, `status = ok`, clock/`clock_valid` updated, later set advances);
  - wrong length (short/long), truncated envelope, wrong `ver`, zero time and
    backward time all return `invalid` and leave the clock unchanged;
  - unknown op / op_id echo, destructive-op shapes, reserved Billows target;
  - every status 0–7 encodes with the right detail, 64 B cap, 59 B detail cap,
    small-buffer truncation and UTF-8 boundary;
  - all three security outcomes and the raw ATT values;
  - the reply-first seam: no handler → `unsupported`; after
    `ble_control_set_action_handler()` the dispatcher plans `ok` +
    `action`/250 ms and does not run it until `ble_control_run_action()`.
- Docs: design 05 §5.6 implementation rules; ADR 0036.

## Deviations / decisions

- Known destructive ops 2/3/4/5/7 answer `unsupported` in T29 (they validate
  their empty body first) rather than pretending to succeed with no handler.
  T48 sets `result.action` and registers the handler; the 250 ms timer runs only
  after the notification. ADR 0036.
- `set_time` requires the exact 13-byte frame. Trailing bytes are `invalid` for
  V0 ops even though design 05 §5.13 allows future payloads to grow.
- Backward corrections map to `invalid` with "clock out of range", not
  `failed`, matching the T20 note that the device may be ahead of the phone.
- Result notifications use the existing `ble_service` callback instead of the
  `ble_tx` live ring; `result` has its own CCCD subscription state.

## Gotchas for later tasks

- **T30:** the `control` characteristic keeps `WRITE_AUTHEN`; keep
  `BLE_GATT_CHR_F_NOTIFY_INDICATE_ENC` on `result` so the CCCD is encrypted.
  The callback-level check is a second line of defence, not a replacement.
- **T48:** use `result.action` + `result.action_delay_ms` from the dispatcher and
  register `ble_control_set_action_handler()`; do not act inside the write
  callback and do not send a second result. Factory reset must wipe before
  scheduling the reboot.
- **T35:** subscribe to `result` before the first `control` write; results sent
  without a subscription are dropped and the app's 3 s timeout is the fallback.
- **MTU:** result chunks are `MTU−3`; the first 5 bytes carry `len`, so the
  client concatenates until it has `5 + len`. `live` remains the 20 B
  notification path.
- **Clock:** `bridge_state_set_time()` fires the live change hook itself; do not
  queue an extra live frame from control.
- **No allocations:** keep the dispatcher/encoder heap-free; the GATT callback
  allocates only the NimBLE mbuf for the notification.
