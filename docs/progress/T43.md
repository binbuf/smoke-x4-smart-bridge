## What landed

- `app/lib/data/ble/ble_client.dart`
  - `BleClient.platformStates`: a named runtime adapter-state stream
    (`ready`, `bluetoothOff`, `permissionNeeded`, `permissionBlocked`,
    `unsupportedPhone`).
- `app/lib/data/ble/flutter_blue_plus_ble_client.dart`
  - maps `FlutterBluePlus.adapterState` to that stream and cancels the
    subscription on dispose.
- `app/lib/data/ble/bridge_link.dart`
  - subscribes to `platformStates`. A blocked adapter clears `_secure`, the
    watchdog, periodic sync, pending controls and GATT subscriptions, then
    enters `ConnectionPhase.blocked` and reports `BlockReason`; `ready` resumes
    the bounded reconnect budget.
  - the archive is keyed by the BLE address (`_device.id`) and the advertised
    name, so the saved `bridge` row is usable for the next launch scan.
- `app/lib/app/bridge_controller.dart`
  - `prepareLaunch()` loads `SampleDao.savedBridge()` and the newest archived
    sample before the first frame. No row → `beginSetup()`; a row → Live in
    `offline` with `lookingForBridge`, last-known probe values, last-known age
    and `offlineCache` derived from real rows.
  - `connectSavedBridge()` runs the bounded 10 s foreground scan by BLE
    identity then name, reuses `connectAndSecure` (stored bond → no prompt), and
    leaves Live with `Looking for the Bridge…` + manual `Connect` when absent.
  - saved identity is touched on every healthy transition; `forgetPhone()` and
    `factoryReset()` remove only the `bridge` row.
  - `retryConnection()`/`refreshLink()` are real now: resume reconnect or rerun
    the launch scan; the old “pretend live after 900 ms” path is gone.
- `app/lib/app/view_state.dart` / `live_screen.dart`
  - `LiveViewState.lookingForBridge` and `launchScanning`;
  - Live notices for `Looking for the Bridge…` + `Connect`, and the named
    BLOCKED state with a Bluetooth/app-settings action.
- `app/lib/app/bootstrap.dart`
  - `prepareLaunch()` before `runApp`, then a non-blocking
    `connectSavedBridge()`.
- Tests: `app/test/launch_connect_test.dart` (10):
  first install → Setup; saved Bridge found by identity with no bond; unrelated
  advertisement never connected; absent after the window; absent render with
  Connect and no Setup; Bluetooth off at launch; blocked render; file-DB
  kill/relaunch loads saved + last-known; forget/reset keep orphaned samples;
  runtime adapter off → BLOCKED → on → reconnect.
- Docs: 06 §6.9 launch/health implementation note; ADR 0047.

## Facts / gotchas for later tasks

- **T46:** use `prepareLaunch` + `connectSavedBridge`; the scan window is
  injectable via `prepareLaunch(scanWindow: ...)` for tests. On a phone the
  window is `bleScanTimeout` (10 s).
- `bridge.id` is now the **BLE address** (e.g. `AA:BB:...`), not
  `info.device_id`. Scan matching uses it first, then `bridge.name`. This is a
  pre-release identity change: old rows keyed by the protocol id still read but
  are not the saved identity.
- `preferred scan` never falls back to the first compatible result; do not add
  such a fallback.
- `BridgeLink` and the controller both listen to `platformStates`. The link owns
  reconnect when `link.device != null`; the controller only re-runs the launch
  scan when there is no link device. Keep that guard to avoid two loops.
- After a real adapter off, `BridgeLink._blocked` must stay true until `ready`;
  `retryNow()` is intentionally a no-op while blocked.
- Widget tests that drive launch must wrap DB/scan work in
  `tester.runAsync(...)`; the launch scan uses a real `Timer` and FakeAsync will
  hang otherwise.
- `SmokeBridgeApp` still routes on `hasSavedBridge`/`phase == setup`; the launch
  controller is responsible for never setting either while a saved row exists.
- Stale bond on launch maps to `Can’t reach the Bridge` (Retry/Forget); the
  approved `Forget and re-pair` instruction still lives in SetupFlow. Surface
  placement is T50/T51.

  identity, not history) and reconcile cursors.
- **T47:** a future launch could match a third saved identity field if the BLE
  address ever changes (Android privacy addresses); today the contract is a
  stable public address.
