# T06 — UI baseline and view-model seam

## What landed

- Production view state in `app/lib/app/view_state.dart`: immutable
  `LiveViewState`, `ProbeView`, `BillowsView`, `HistoryViewState`,
  `SetupViewState`, `SettingsViewState` and `BridgeDetailsViewState`.
  `BridgeController` builds them via `liveView`, `historyViewFor()`,
  `historyView`, `setupView`, `settingsView` and `bridgeDetailsView`.
- Screens and shared widgets now render view state: Live, History, full-screen
  chart, Settings root, Bridge details, Billows, About, History & storage,
  Appearance, Setup, Saved history and the OLED preview. Controller reads remain
  only for actions (`setUnits`, `retryConnection`, navigation, dialogs).
- Data seam: `app/lib/domain/content.dart` (`BridgeContent`,
  `EmptyBridgeContent`, `HistoryWindow`) and Flutter-free
  `app/lib/domain/models.dart` (enums, `ChartPoint`, `ChartSeries`,
  `HistoryFixture`, cooks, stats).
- Fixtures moved to `app/lib/debug/fixtures.dart`; the fixture-backed
  `DemoBridgeContent` and `demoBridgeController()` are in
  `app/lib/debug/demo_content.dart`. Production screens do not import either.
- Production formatter layer: `app/lib/app/formatters.dart`.
- Scenario lab moved to `app/lib/debug/scenario_lab.dart`; the gate moved to
  `app/lib/app/lab_gate.dart`. `SmokeBridgeApp`/`AppShell`/`SettingsScreen` take
  an `enableExperimentalLab` override so release hiding is testable.
- Tests: `app/test/view_state_test.dart` covers the five view states, empty
  production content, controller-free `ProbeCard` rendering, release lab hiding
  and a source guard against `debug/fixtures.dart`, `debug/demo_content.dart` and
  `prototype/` imports.
- The screenshot tool still generates from the production screens; it injects
  `demoBridgeController()` for the approved baseline. Existing PNGs match
  unchanged.
- ADR: `docs/design/adr/0017-immutable-view-state-seam.md`.

## Gotchas for later tasks

- **M2/M3**: replace `EmptyBridgeContent` with a live/archive-backed
  `BridgeContent`. Do not add fixture reads to screens; add data to the content
  implementation and keep the view-state builders.
- The controller still owns prototype simulation methods (`simulateSync`,
  `simulateSave`, `retryConnection` timers) and fixture-shaped default bridge
  metadata (`deviceId`, `firmware`, battery, RSSI). Real wiring replaces these in
  M2/M4; T64 must remove/hide simulation paths from release.
- `DateTimeRange` in controller/view state is Flutter's material type. The domain
  layer uses `HistoryWindow` to stay Flutter-free.
- `demoBridgeController()` is the test/screenshot constructor. Plain
  `BridgeController()` uses `EmptyBridgeContent`: four disconnected probes, no
  history, no cooks, `—` saved-data range.
- `HistoryViewState.for` gap override: screens call
  `controller.historyViewFor(hasGap: ...)`; the bare `historyView` getter uses the
  normal gap.
- The app shell still imports the debug lab in debug builds; only the entry is
  gated. T64 owns a hard release import-graph check.
- Cook day labels are relative to `HistoryViewState.now` (content clock), not
  `DateTime.now()`, so tests stay deterministic.
