# T07 — BLE fake and app test seam

## What landed

- Production BLE seam: `app/lib/data/ble/ble_client.dart` with `BleClient`,
  `BleDevice`, `BleConnectionState`, `BleBondState`, `BleFailure`,
  `BleException`. Methods: `scan`, `stopScan`, `connect`, `disconnect`, `bond`,
  `requestMtu`, `read`, `write`, `notifications`, `setNotify`, `dispose`.
- `BridgeController` and `createBridgeController` accept an optional `BleClient`.
  `main.dart` is unchanged. The controller disposes an injected client.
- Scripted fake, test support only:
  - `app/test/support/fake_ble_client.dart` — ads, connect/disconnect, bonding,
    MTU, security gating, notification chunking at `MTU-3`.
  - `app/test/support/fake_bridge.dart` — GATT server for `info`, `live`,
    `config`, `stats`, `control` results and framed `sync_ctrl`/`sync_data`.
  - `app/test/support/fake_gatt_server.dart` — peripheral-side interface.
  - `app/test/support/fake_bridge_session.dart` — test link harness folding live
    notifications into a `BridgeContent` and mapping disconnect to offline.
  - `app/test/support/codecs.dart` — the only bridge to
    `protocol/gen/records.dart` plus characteristic lookup helpers.
- Tests: `app/test/ble_fake_test.dart` (8) and
  `app/test/ble_widget_flow_test.dart` (1 widget test: scan → connect → bond →
  subscribe → live → disconnect).
- Docs: `docs/design/adr/0018-ble-client-seam-and-scripted-fake.md`,
  `docs/design/06-app.md` §6.2/§6.10.

## Gotchas for later tasks

- `app/lib/` **cannot** import `protocol/gen/records.dart`; Dart package rules
  reject imports above the package root. The fake reaches it from
  `app/test/support/codecs.dart`. T32 must package or relocate the generated Dart
  codec for production instead of copying bytes.
- Fake notifications are broadcast streams. In pure `test()` add
  `await Future<void>.delayed(Duration.zero)` after a state transition before
  asserting the stream.
- `testWidgets` runs in fake async. BLE calls with `Future.delayed` hang unless
  wrapped in `tester.runAsync(...)` (see `ble_widget_flow_test.dart`).
- `FakeBleClient` requires a device to be in its scripted advertisement list
  before `connect`. Security comes from generated characteristic metadata:
  `info` is open; `live`/`stats`/sync are encrypted; `control`/`config` are
  authenticated. Bonding is the fake's encryption/auth gate.
- Bond state persists across a fake disconnect, like a platform bond; MTU resets
  to 23 on reconnect.
- `FakeBridge` sync frames are sized to `min(240, MTU - 3 - 4)`; first frame has
  START, last has END, and the logical stream is START + records + END.
- `FakeBridgeSession` sets the initial controller phase to `setup` and drives
  `live`/`offline` from fake link events. It is not a production link layer.
- Setup UI still uses T06 review timers. T33 owns replacing them with
  `BleClient` scan/bond calls.
