## Gotchas for later tasks
- **Widget tests that drive the real link:** wrap the sync procedure in
  `tester.runAsync(...)`. In the `testWidgets` fake-async zone a bare
  `await link.connectAndSecure(...)` hangs on the fake client's
  `Future.delayed(Duration.zero)`.
- **Pending timers:** dispose the link (`await link.dispose()`) inside the test
  body; `addTearDown(controller.dispose)` alone can run after the timer check.
- **Store clock:** `RecentHistoryStore` takes `now`; the controller wires it to
  `content.now`. A fixed-time test must give its content the same fixed clock as
  the records and `BridgeLink.nowUtc`.
- **Fixture type split:** `BridgeSampleRecord` (app wire) vs `SampleRec`
  (generated test codec). `test/support/recent_history.dart` returns `SampleRec`
  for `FakeBridge`; map it to `BridgeSampleRecord` in store tests.
- **Empty semantics:** `hasAnyHistory` is store data or `historyHasData`.
  Defaults are honest (`false`); `demoBridgeController` opts in.
- **Custom range:** `entireHistoryRange` follows the store when records exist,
  so the custom sheet spans only the recent window in V0.
- **Only one gap band:** painter breaks at every >90 s hole, but only the widest
  hole gets the labelled band. Multi-band support is T42/T45.

## Post-T36 hardening (2026-10-27)

### Firmware
- **Real X4 receive fixed:** the SX1262 was tuned with the SX127x-era sync byte
  `0x12`, so it searched for `0x0012` and never matched. It now uses `0x1424`,
  reads the register back after init, and the TCXO is back to the T10-proven
  3.3 V. Four real X4 frames at ~30 s cadence, RSSI −35 dBm, were stored and
  synced to the phone. Evidence: `artifacts/bench/T37/lora-rx-after-syncword-fix.log`.
- **BLE long-read fix:** `read_value()` now appends the complete value and lets
  NimBLE slice Read Blob responses; the previous chunking produced
  `GATT_INVALID_OFFSET` on `info`.
- **Stable identity/advertising:** public identity address wins, the local name
  and `info.device_id` use printed MAC order, `ble_service_keep_advertising()`
  plus the housekeeping tick recovers a missed advertising start, and the GAP
  name is kept in step with the scan-response name.
- **Passkey root cause:** `ble_gap_adv_start()` now receives the real GAP
  callback, so `PASSKEY_ACTION`/`PARING_COMPLETE` reach the service. The OLED
  passkey wakes a sleeping panel, and the Probes strip blinks `BT` while
  advertising.
- **sample_pipe:** the 0-tick delay that starved IDLE0 was fixed in `5ffe6c6`
  and recorded in `progress/T21.md`.

### App
- **Discovery:** scanning is unfiltered and filtered in Dart; split
  advertisement + scan-response reports are merged and re-emitted.
- **Setup:** a failed connect has its own `connectionFailed` page with
  retry-without-rescan; failed selects disconnect so the Bridge re-advertises;
  the first-sync page waits for the real recent pass before enabling
  `View live readings`.
- **Link:** phone→Bridge RSSI is read; forward sync runs quietly every 30 s
  (not 60 s); live notifications feed `RecentHistoryStore` so sparklines and
  History move between syncs.
- **Live UX:** the chain shows separate BLE and LoRa signal meters and link
  durations; a lost/unpaired X4 uses one amber warning on the X4 node and a
  dialog instead of the old inline notice; probe tiles show a Min/Max range
  line and a signed change over the configurable *Live change window* (default
  5 min).
- **Settings:** `Live change window` (1/5/10/15/30/60 min) is a local
  preference next to Temperature units.
