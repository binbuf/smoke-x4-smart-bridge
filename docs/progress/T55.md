# T55 — Bench: all settings and actions

**Date:** 2026-10-28 · **Verification:** P (Pixel 11 Pro Fold + Heltec V3) ·
**Result:** partial pass. Every app-driven setting/action was walked on the real
bridge and phone, and two release defects were found and fixed. Continuation 1
added the seeded `Not synced` / permanent-loss recheck. Two physical checks
remain (OLED photo, X4 SYNC re-pair); the detailed evidence table is
`artifacts/bench/T55/README.md`.

## What landed

- **Firmware fix (release-blocking):** `sample_log/log_flash_core.c` clear scan
  used a 4,096 B stack buffer on the 3,584 B `esp_timer`/main tasks. The first
  `clear_history` panicked (`InstrFetchProhibited`, PC `0x1000`) and every boot
  repeated it through `clear_pending`. It now scans in 256 B chunks. Retested
  clear, app-killed-mid-clear, and reboot-after-clear on the board. ADR 0060,
  design 03 §3.7.
- **App fix:** Setup scan rows printed the advertisement sentinels as
  `P4 -3277°F · 255%` after a blank/reset Bridge. `BridgeAdvertisement.preview`
  is now nullable and omits an invalid/detached temperature and unknown battery;
  `setup_codec_test.dart` covers invalid, detached and unknown-battery cases.
  Design 06 §6.4 updated.
- **Bench evidence** under `artifacts/bench/T55/` (release APK, serial logs,
  screenshots at 390/320 dp dark and light, backups/hashes in `backup/`).
- **Continuation 1:** seeded debug archive on the real phone. `Not synced` band
  label renders in 24 h at 390 and 320 dp; the permanent-loss banner appears
  below Summary/Cooks; 1 h range drops both the banner and the 117-day cook
  (range-scoped). Real archive, release APK and live X4 link were restored
  afterwards.
- Release image: `02E2E2B4DA3013E14E3AED57A2D5505417B5214C263F2C7F43009ED3340F61F6`
  (603,472 B). Release APK:
  `2E095C5343D0D7350B574EE376A9E7D59963571745363296026ABD6B1505F28C`.

  `sx4.ble: config applied: units …, timeout …, name …`; persistence across
  force-stop/relaunch and a bridge reboot.
- Appearance dark/light and Live change window: immediate, persisted, tile
  footer follows the window.
- Settings/Bridge details connected and offline at 320 dp in both themes: one
  Bridge section, one History & storage row, one Sync now/Disconnect, no
  save-all, no `Device log`, no Experimental lab in the release APK.
- Forget: confirmation copy, `result ok`, bond removed (`0 bond(s) remain`),
  re-advertise, app returns to Setup with `History on this phone` (2,611 rows).
- Wrong passkey: named `The code didn’t match`; correct re-pair then succeeded.
  The Android “Try again” path landed on `Couldn’t connect` and needed
  `Find another Bridge`; recorded as a follow-up, not retested twice.
- Clear history: exact count/range sheet, `ok`, Bridge 0, phone rows kept, new
  `stored seq=0`, reboot showed a new generation (`f2fed1b3`).
- Kill the app 150 ms after confirming clear: bridge finished the clear
  (`stored seq=0`) with no panic; relaunch showed Bridge 2 / phone 2,600.
- Power off: `Bridge is off` screen, Vext off, SX1262 asleep, no advertising;
  DTR-held PRG (GPIO0) wakes it and the app reconnects after relaunch.
- Factory reset: exact four-loss copy, `result ok`, reboot with 0 records and
  `0/4 bond slot(s)`, app Setup, phone history kept (2,620), then a fresh pair.
- T46a re-check: offline probe semantics, sparkline backfill, saved-ID header,
  blocked banner without sync card, `Showing saved readings` banner, and the
  110 s bridge-reboot recovery (X4 `Receiving readings` at ~125 s).
- Seeded History re-check (continuation 1): `Not synced` dashed band label in
  24 h at 390/320 dp, permanent-loss banner with the same period blank, and
  range-scoped Cooks/loss (1 h range has neither the banner nor the long cook).
  Artifacts `seed-01`-`seed-05`.
- Pairing cap: host `ble-adv` bond-limit test plus the app’s full-store widget
  test (no five physical phones).

## Deviations / gotchas for later tasks

- **Do not restore a pre-run NVS image after re-pairing the phone.** It brings
  back a stale bond the phone no longer has and the app then loops on
  `disconnected reason 0x23d`. To finish this run the board was restored from
  the pre-run NVS+samples backup, phone bonds were cleared with a temporary
  one-time `bridge_config_clear_bonds()` boot call, the phone was re-paired, and
  the release image was reflashed. The final state has 1 bond, 1 X4 pairing, the
  pre-run generation/log, and a working link.
- A temporary `ESP_LOGI("BENCH passkey %s")` was used to read the OLED code while
  the webcam was black. Both temporary firmware changes are reverted; the
  committed image hash above is clean.
- `firmware/bench/t10_probe/tools/capture.py` can crash printing a replacement
  character to a cp1252 console. The capture file is still complete up to that
  line; prefer `python -X utf8 -m ...` or redirecting to a file.
- Opening `serial.Serial()` then setting DTR/RTS pulses EN and reboots the board.
  Set `dtr=False, rts=False` on the unopened `Serial()` object first.
- `wm density 540` gives 320 dp on this 1080 px phone; restore 390 after the run.
- The release APK is debug-signed, so `adb install -r` keeps app data/bonds.
- Clearing history runs on the timer task: keep the sweep buffer small (ADR
  0060). The bench retest, not the host suite, is the stack regression gate.
- Scan previews must omit sentinels; `-32767`/`-32768` and battery `255` are not
  temperatures/percentages.
- **Fold screenshots:** `screencap` sees two displays; use
  `dumpsys SurfaceFlinger --display-id` and `screencap -d 4619827677550801153`,
  writing on-device then pulling. PowerShell `>` writes UTF-16 and corrupts PNG.
- **Seeded archive needs a debuggable install.** The release APK is not
  debuggable, so `run-as` fails. Install `app-debug.apk` over it (same debug
  signature, data kept), back up the real DB with
  `adb exec-out run-as ... cat databases/smoke_bridge.db`, seed, then copy the
  archive back and reinstall the release APK. Bluetooth off keeps the app on the
  saved archive.
- `tools/bench/t46_seed_db.py` overlays the Yesterday `Bridge off` hole and the
  14 h..6 h `Not synced` gap, so both labels collide. The T55 run used a local
  variant with only the `Not synced` gap; the shared tool was left alone because
  T46 evidence cites it.
- At 320 dp the History offline banner and filter chips truncate
  (`Turn Bluetooth on to find your ...`, `24 ho...`, `All pro...`). Settings at
  320 dp is fine; file this under T54/T50 rather than fixing it in T55.
