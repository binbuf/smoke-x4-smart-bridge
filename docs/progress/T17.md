# T17 - sample_log: record codec

## What landed

- `firmware/components/sample_log/include/log_core.h` / `log_core.c`:
  firmware-facing record codec. Wraps generated `sx4_sample_rec_encode` /
  `sx4_sample_rec_decode` and adds:
  - `SAMPLE_LOG_RECORD_SIZE` (18) and `sample_log_record_size()`;
  - `sample_log_record_validate()`: probe attached bit 0 <=> `TEMP_DETACHED`
    (symmetric; `TEMP_INVALID` is a valid attached value);
  - `sample_log_record_encode()` / `_decode()` returning
    `sample_log_status_t` (`OK`, `ERR_ARGUMENT`, `ERR_SIZE`, `ERR_CRC`,
    `ERR_LAYOUT`);
  - decode into a local, copy out only on success (no partial record);
  - `sample_log_record_probe_attached()`.
- `firmware/components/protocol_gen/CMakeLists.txt`: ESP-IDF component that
  compiles the committed `protocol/gen/records.c` and exports its include dir.
  `sample_log` now `REQUIRES esp_common protocol_gen`.
- `firmware/test/test_sample_log_rec.c` (`sample-log-rec` CTest) with layout,
  CRC, sentinel, flags, bounds and corruption coverage.
- ADR 0025; design 04 section 4.2 updated.

## Key facts for later tasks

- The byte layout/CRC/u24 codec is still generated; `log_core` is only the
  semantic firmware boundary. Do not re-implement offsets or CRC in
  `sample_log`.
- T18 ring code should include `log_core.h`, call `sample_log_record_decode()`
  and `sample_log_record_encode()`, and advance/allocate by
  `sample_log_record_size()`. A bad tail is `ERR_CRC` or `ERR_LAYOUT`; both mean
  "stop the scan".
- `sample_log_record_decode()` accepts `len >= 18` and consumes exactly the
  first 18 bytes; trailing bytes are ignored for forward versioning.
- `sample_log_record_validate()` is available for recovery scans that already
  have a decoded struct.
- Sentinels: `SX4_TEMP_DETACHED` = -32768, `SX4_TEMP_INVALID` = -32767
  (`records.h`). Attach bits are bits 0-3, Billows 4, clock 5, Celsius 6,
  alarm 7.
- `firmware/test/CMakeLists.txt` defines `sx4_sample_log_core` (links
  `sx4_protocol_gen`) and `test_sample_log_rec`; extend that suite rather than
  adding a new build tree.
- Host build on this bench: prepend `C:\msys64\ucrt64\bin` to `PATH` (gcc
  16.1.0, cmake 4.4.0, ninja 1.13.2).
- Firmware build: set `IDF_PYTHON_ENV_PATH` and dot-source
  `D:\esp\esp-idf\export.ps1`; then `idf.py -B build
  "-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.heltec-v3"
  build` from `firmware/`.
- New IDF components are picked up automatically from `firmware/components/`;
  the `COMPONENTS main espcoredump` whitelist builds transitive requirements.

## Follow-ups

- T18: consume `log_core` for record encode/decode and use
  `sample_log_record_size()` for stride; treat `ERR_CRC`/`ERR_LAYOUT` as the
  torn/impossible tail.
- T19: include `protocol_gen` transitively through `sample_log`; do not add a
  second copy of `records.c`.
- T21: map `ERR_LAYOUT`/`ERR_CRC` to the log-drop counter rather than storing a
  partially decoded sample.
- Future record growth: change `protocol/records.yaml`, run `make protocol`,
  and let the compile-time asserts in `log_core.h` and the sector-header version
  gate the change.
