## What landed

- `firmware/components/ble_service/ble_control.c` / `include/ble_control.h`
  - `control` writes >16 B now return `invalid` with "control too long".
  - `ble_control_run_action()` returns the backend `SX4_RESULT_STATUS_*`.
  - Dispatcher rules/evelope/`op_id` echo unchanged from T29.
- `firmware/components/ble_service/ble_control_actions.c` / `.h`
  - Pure router: forget/factory/power/clear/unpair callbacks; null or unknown
    action/callback → `unsupported`; callbacks return contract status codes.
- `firmware/main/boot.c`
  - Registers the backend with `ble_control_set_action_handler()` before
    `ble_service_start()`.
  - forget → `ble_service_forget_current_peer()`.
  - factory → `bridge_config_factory_reset()` then a 50 ms `esp_restart()`
    timer (immediate restart only if the timer cannot be created).
  - power → Vext off, `sx_radio_sleep()`, `board_enter_deep_sleep()`.
  - clear → `sample_log_clear()`; unpair → `sx_radio_unpair()`.
- `firmware/components/ble_service/ble_service.c`
  - `ble_service_forget_current_peer()`: delete the current conn's peer bond,
    terminate the link; disconnect path re-advertises; other bonds stay.
  - Late action failures are logged (result already sent).
- `firmware/components/sample_log/`
  - New `log_flash_clear()` runtime path and `sample_log_clear()` wrapper.
  - `log_flash_hooks_t` gained `begin_clear`; `log_flash.c` wires it to
    `bridge_config_begin_log_clear()`.
  - `sample_log.c` serializes append/read/info/clear with one mutex.
- `firmware/components/sx_radio/`
  - `sx_radio_unpair()` and a pairing mutex shared with `radio_rx`, so the BLE
    action cannot race the FSM.
- Tests
  - New `test_ble_control_actions.c` (`ble-control-actions`): per-op ordering,
    idempotency, failure mapping, op_id echo, malformed/wrong-length, >16 B,
    unknown op, Billows always unsupported, missing backend/handler.
  - `test_sample_log_flash.c`: runtime clear success, begin failure keeps ring,
    erase failure is READ_ONLY and the next boot resumes `clear_pending`.
- Docs: 05 §5.6, 03 §3.9, ADR 0052.

## Facts / gotchas for later tasks

- `ble_control_action_fn` now returns `uint8_t` (contract status). Any old
  `void` handler will not compile; update call sites.
- The 250 ms timer only *plans* the action. The real effect runs after the
  result notification; a failure there is log-only by design.
- `bridge_config_factory_reset()` already wipes config keys, sets a new
  generation + `clear_pending`, and calls the NimBLE bond-store clear. Boot
  recovery finishes the sector erase. Do not add a second erase path.
- `log_flash_clear()` erases only non-blank sectors, then `log_ring_format()`s
  in memory. A failed begin leaves the old ring usable; a failed erase leaves
  `clear_pending` set and the log READ_ONLY until reboot.
- `sample_log.c` owns a mutex now. Do not call `sample_log_*` recursively from
  inside the log adapter.
- `sx_radio_unpair()` takes the pairing mutex; it is safe from the BLE timer
  task but still does SPI via the tune callback. T49 owns deeper radio/BLE
  teardown ordering.
- T47's config image is not known to be on the bench board; the T48 image is
  built/hashed only and must be flashed in T55.
