## What landed

- `firmware/components/ui/include/ui_button.h` + `ui_button.c`
  - `ui_button_t` + `ui_button_sample(button, raw_pressed, now_ms,
    consume_press)`: 20 ms sampling contract, 30 ms debounce, tap < 400 ms,
    countdown from 400 ms, release >= 1.5 s commits, release in
    [400, 1500) cancels.
  - Events: `NONE`, `PRESS`, `TAP`, `HOLD_START`, `HOLD_TICK`, `HOLD_CANCEL`,
    `HOLD_COMMIT`. `PRESS` fires on the debounced down edge.
  - `ui_button_countdown_s()`: 2 then 1 while held, 0 at/after 1.5 s
    ("release to confirm") and when idle.
  - A press whose edge is sampled while the panel is asleep is consumed for
    its whole duration: `PRESS` still fires so the caller can wake, but no
    TAP/HOLD events follow. There is no wake-then-power-off in one press.
  - `ui_boot_hold_t` + `ui_boot_hold_sample()`: WAIT/CONFIRMED/RELEASED;
    raw release before 1.5 s returns RELEASED immediately.
- `firmware/components/ui/ui.c`
  - ui task waits at most `UI_BUTTON_SAMPLE_MS` (20 ms) in every state and
    samples `board_prg_pressed()`; it no longer blocks forever on display
    sleep.
  - TAP: storage notice -> `ui_dismiss_storage_failure()`; any other overlay
    -> no-op; otherwise `ui_page_next()`.
  - HOLD_START/TICK -> `ui_display_activity()` + `ui_set_power_off(digit,
    true)`; CANCEL -> `ui_set_power_off(0,false)`.
  - COMMIT -> `ui_set_overlay_mask(UI_OVERLAY_MASK_OFF)` (and clear
    POWER_OFF), render, 300 ms, `board_power_off_vext()`,
    `sx_radio_sleep()`, `ble_service_stop()`, `board_enter_deep_sleep()`.
    If deep sleep fails, clear OFF and stay on.
  - Physical panel `0xAF` is applied (a) when `s_wake_requested` is consumed or
    (b) if the view is awake and the panel is off. Sample dirty marks still do
    not wake the panel.
- `firmware/main/boot.c`
  - `confirm_wake_hold()` runs before NVS and only when
    `esp_sleep_get_wakeup_causes() & (1u << ESP_SLEEP_WAKEUP_EXT1)`.
    Cold/USB/EN boots skip it. Release before 1.5 s re-enters deep sleep with
    no BLE/UI. `ui_init()` consumes the hold tail.
  - Calls `board_prg_init()` in the normal sequence.

## Facts for later tasks

- **Constants live in `ui_button.h`**: 20/30/400/1500 ms, countdown starts at
  400. Change them there, not in `ui.c`.
- `ui_button_sample()` takes `consume_press`; pass `true` only when the panel
  was asleep at the press edge. It is read only on the press edge.
- The hold threshold is judged on the **raw release timestamp**
  (`candidate_since_ms`), so a release at exactly 1500 ms commits and 1499 ms
  cancels even though the level debounce completes 30 ms later.
- A raw release after 400 ms can emit `HOLD_START`/`HOLD_TICK` while the
  debounce runs; the terminal event is the following `HOLD_CANCEL`/`COMMIT`.
- `ui_button_countdown_s()` does **not** depend on `countdown_shown`; it only
  needs `stable`, not `consumed`, and elapsed in [400, 1500).
- Boot confirmation is gated on EXT1 only. Do not generalize it to every reset:
  USB flashing and EN reset must still boot normally.
- The ui task is now a 20 ms poller while display-asleep. Panel I2C stays off;
  there is no render while `s_view.asleep`.
- `ui.c` needs `esp_driver_gpio`, `esp_driver_i2c`, `esp_timer`, `freertos`,
  plus `board`, `ble_service`, `sx_radio`. `main` needs `esp_timer` in
  `REQUIRES` (build error otherwise).
- IDF 6.0.2 deprecates `esp_sleep_get_wakeup_cause()`; use
  `esp_sleep_get_wakeup_causes()` and test the EXT1 bit.
- GPIO0 stays the ROM strap. The deep-sleep arm is `EXT1 ANY_LOW` (ADR 0020).
  T09's 20/20 was USB/DTR; the physical count is T62.
