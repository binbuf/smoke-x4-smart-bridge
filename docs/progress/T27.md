# T27 — ble_service: GATT server and `info`

**Date:** 2026-10-27 · **Verification:** host/CI + firmware compile · **Result:** done
**Board:** phone/scanner discovery and the real 32-byte read deferred to T37; the host byte vectors and the image guard are the gate now.

## What landed

- `firmware/components/ble_service/include/ble_info.h`, `ble_info.c` — pure C11
  encoder for the fixed 32-byte `info` payload:
  - `ver = 1`, generated protocol major/minor, fixed field offsets;
  - `BLE_INFO_CAPS_ALL` requests every MVP cap and the encoder always clears
    `billows_control` (bit 1), so the wire caps byte is `0xFD`;
  - NUL-padding/truncation rules for `device_id` (4), `fw` (12), `model` (8);
  - `bonds_free` clamped 0–4, `probes` rule (paired 2/4 else 4).
- `firmware/components/ble_service/include/ble_gatt_spec.h`,
  `ble_gatt_spec.c` — the eight-slot table (`0001`–`0008`) with the generated
  `SX4_BLE_CHAR_*` properties/security. No Wi-Fi/OTA/DFU slot exists.
- `firmware/components/ble_service/ble_service.c` — NimBLE server:
  - 128-bit service `7f9b0000-4c5b-4b0f-9a3d-1c2e3f405162` and all eight
    characteristic UUIDs;
  - `info` open Read, Read Blob capped at `MTU−1` per response;
  - `live`/`stats` encrypted reads, `control` authenticated write,
    `result`/`sync_data` encrypted Notify, `sync_ctrl` encrypted write,
    `config` authenticated read/write;
  - NimBLE auto-adds the standard CCCD on every Notify slot; the
    `BLE_GATT_CHR_F_NOTIFY_INDICATE_ENC` flag applies the characteristic's
    encryption level to the CCCD write;
  - `nimble_port_init()`, preferred MTU 247, GATT service registration,
    a GAP event listener for connect/disconnect, and `ble_service_stop()` that
    stops/deinits NimBLE. **Advertising is not started** (T30).
  - V0 placeholders: `live`/`config`/`stats` read a zeroed buffer with `ver=1`
    and writes to `control`/`sync_ctrl`/`config` are drained but not acted on.
    T28/T29/T31/T47 replace them.
- `firmware/test/test_ble_info.c` + `ble-info` CTest — exact byte vectors for
  all caps and for `billows_control = 0`, field padding/truncation/clamping,
  probe rule, argument errors, and the slot table (8 slots, properties,
  security, CCCD exactly on Notify, no network/OTA names).
- Build boundary: `firmware/components/esp_wifi` is a project override that
  exposes the IDF headers and compiles one empty marker. IDF 6's `bt` requires
  `esp_wifi`, but its hidden `ESP_WIFI_ENABLED` cannot be turned off; without the
  override the image pulled the Wi-Fi stack, wpa_supplicant, lwIP and esp_netif.
- `firmware/compat/include/lwip/ip_addr.h` — empty header shim for the IDF
  disabled-Wi-Fi path where `esp_mesh.h` includes lwIP but `esp_common` has no
  lwIP include path. No lwIP object is linked.
- `firmware/tools/check_image.py` — now interprets "no network stack" at the
  linked-object level: HTTP/TLS/MQTT/OTA components stay forbidden, while inert
  build deps (`esp_wifi`, `lwip`, `esp_netif`, `esp_netif_stack`,
  `wpa_supplicant`) are allowed only if no object from their archives appears
  in the linker map.
- `firmware/CMakeLists.txt` builds `bt`; `sdkconfig.defaults` enables NimBLE,
  peripheral/broadcaster roles, NVS bond persistence, 4 bonds/1 connection,
  MTU 247, LE Secure Connections; lwIP stays disabled.
- `firmware/components/bridge_config/CMakeLists.txt` now privately requires
  `bt` because `bridge_config_nvs.c` uses `ble_store_clear()` when NimBLE is
  linked.

## Gotchas for later tasks

- **Do not remove the `firmware/components/esp_wifi` override.** IDF's real
  component silently returns; `bt` hard-requires it and its hidden
  `ESP_WIFI_ENABLED` defaults to `y`. The override provides headers only; a new
  Wi-Fi API call fails at link time by design. See ADR 0034.
- **`info` is built on every read**, so `bonds_free` is current after a bond
  without a reboot. `device_id` comes from `ble_hs_id_copy_addr(PUBLIC)`;
  NimBLE must be synced before the value is meaningful (`0000` is the fallback).
- **Read Blob slicing:** the access callback appends the prefix up to
  `offset + min(remaining, MTU−1)` and NimBLE slices from `offset`. Do not
  append only the remaining bytes; NimBLE subtracts the offset again.
- **CCCD:** NimBLE adds `0x2902` automatically for Notify characteristics. The
  security of that CCCD write comes from
  `BLE_GATT_CHR_F_NOTIFY_INDICATE_ENC`, not from a custom descriptor callback.
- **T30 seam:** `ble_service_gap_event()` is already registered through a GAP
  event listener and tracks `ble_service_is_connected()`. T30 should also pass
  the same callback to `ble_gap_adv_start()` and add restart-on-disconnect.
  T27 deliberately never advertises.
- **Placeholder reads/writes:** `live`/`config`/`stats` currently return a
  ver=1 zero buffer, and writes are drained no-ops. T28/T29/T31/T47 must replace
  the handlers, not add duplicate characteristics.
- **Version string:** `BLE_INFO_FW_VERSION` in `ble_info.h` must stay equal to
  `UI_VERSION` in `ui_render.h` (`0.1.0`).
