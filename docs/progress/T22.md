  - `board_oled_reset_pulse()` drives RST low/high 20 ms each.
- `firmware/components/ui/include/ui_render.h` + `ui_render.c`
  - `ui_framebuffer_t` = 8 pages x 128 bytes = 1024 B, SSD1306 page order.
  - `ui_snapshot_t`, `ui_page_t`, `ui_overlay_t`.
  - 5x7 body font in a 6x8 cell (21 cols x 8 rows), 12x24 7-segment passkey.
  - Pages: Probes, Connection, Billows, Bridge. Overlays: boot, storage,
    power-off countdown, passkey, clearing log, resetting, off.
  - `ui_fb_extract_row()` converts a text row back to UTF-8; used by tests and
    handy for diagnostics. Dots decode `*`/`o`, degree and em dash as UTF-8.
- `firmware/components/ui/include/ui_sleep.h` + `ui_sleep.c`
  - `ui_view_t` owns page/asleep/timeout/last activity.
  - sleep at `elapsed >= timeout`; 0 = never; wake never changes page.
  - `ui_view_next_page(view, billows_visible)` skips Billows until detected.
- `firmware/components/ui/include/ssd1306.h` + `ssd1306_core.c`
  - init sequence, `0xAE`/`0xAF`, eight page writes (cmd 0xB0|page, 0x00, 0x10
    then 128 data bytes), all through a write callback.
- `firmware/components/ui/ui.c`
  - 400 kHz I2C master, device 0x3C, reset pulse, boot splash.
  - render task (4096/3/core0) builds the snapshot from bridge_state/config/
    sample_log, renders, compares with the last frame and flushes only on diff.
  - `0xAE` + block on notification while asleep; `0xAF` + redraw on wake.
  - 1 Hz tick only on Connection and Bridge (the pages with time fields).
  - UI dirty flag is set-only; it notifies only while awake, so samples cannot
    wake the panel. `ui_display_activity()`/`ui_wake()` notify.
- `firmware/test/test_ui_render.c`, `firmware/test/goldens/ui/*.fb`,
  `firmware/test/goldens/ui/README.md`, `tools/ui_fb_to_png.py`.

## Facts for later tasks

- **All label rendering goes through the font/UTF-8 path.** `°` is
  `\xC2\xB0`, `—` is `\xE2\x80\x94`; do not paste a raw single-byte dash and
  expect the extractor to see it.
- Row geometry: x = col*6, y = row*8. Left/right and centered text are
  column-aligned so `ui_fb_extract_row()` works. Do not right-align by pixels.
- Text rows are 21 columns. `Attach antenna before` is exactly 21; the splash
  wraps `power` to the next row. `BILLOWS` and `DETECTED`/`NOT DETECTED` share
  row 0 (the phrase does not fit contiguously on 21 columns).
- Overlay masks are `UI_OVERLAY_MASK_*` bits; overlay identifiers are
  `UI_OVERLAY_*` enum values. Keep them distinct (same-name macros caused a
  compile error once).
- Priority: `off > resetting > clearing > passkey > power-off > storage > boot`.
  `ui_effective_overlay()` is the only place that decides.
- Storage failure is ORed in from `sample_log_storage_ok()`; the boot opacity
  is cleared after >=300 ms. `ui_dismiss_storage_failure()` hides the overlay
  for this boot only; the Probes status strip still shows `!`.
- The render task distinguishes a dirty notification from a wake request with
  `s_wake_requested`: a sample that races with the sleep transition cannot turn
  the panel back on. `ui_wake()` only sets that flag when the view was asleep.
  T23 must call `ui_wake()` for wake, not `ui_mark_dirty()`.
- Page changes/overlays call `ui_mark_dirty()`, so they render on the next task
  wake. They do not wake a sleeping panel except through `ui_wake()` /
  `ui_display_activity()` (BLE connect/pairing paths use the latter).
- `ui_set_display_timeout()` accepts only 0/30/60/120; the initial value comes
  from `bridge_config_get_display_timeout()` (default 60).
- Firmware snapshot still has placeholders owned by later tasks:
  `app_connected=false`, `phones_paired=0`, name = configured device name
  (not the BLE `SmokeX4-XXXX`), battery from `bridge_state` (T24 fills it).
- Goldens are regenerated with `SX4_UPDATE_UI_GOLDENS=1`; always review the PNG
  output (`tools/ui_fb_to_png.py`) before committing a changed `.fb`.
- Firmware build uses IDF 6.0.2. The `ui` component needs `esp_driver_i2c`,
  `esp_driver_gpio`, `esp_timer`, `freertos` in PRIV_REQUIRES; `board` needs
  `esp_driver_gpio` + `freertos`.
