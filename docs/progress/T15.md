# T15 — bridge_config: typed NVS store

**Date:** 2026-10-26 · **Verification:** host/CI (no board) · **Result:** done

## What landed

- `firmware/components/bridge_config/include/bridge_config.h` — the typed API:
  pairing, device, log/generation, clock anchor, stats, reserved Billows,
  bond-store wrapper, factory-reset table, KV/random/bond hooks, and the
  `ESP_PLATFORM`-only `bridge_config_init()`. Pure C11, so the host suite
  compiles the same header without ESP-IDF.
- `firmware/components/bridge_config/bridge_config.c` — the core:
  - namespaces `pair`, `device`, `log`, `stats`, plus `meta/config_version`;
  - little-endian blob codec, in-memory cache, defaults (units °F, timeout 60 s,
    name `Smoke X4 Bridge`);
  - full-record validation before any write (902–928 MHz, probes 2/4,
    printable-ASCII ID, UTF-8 name 1–15 bytes, timeout {0,30,60,120}, units
    0/1, valid clock needs a non-zero anchor);
  - version gate and `migrate_v0_to_v1()` (scrub wrong-sized values, keep valid
    keys, ensure generation, then write version 1); future versions return
    `BRIDGE_CONFIG_ERR_VERSION` without writing;
  - random generation on `begin_log_clear`, factory reset, whole-log
    corruption; generation written before `clear_pending = 1`; explicit
    `set_generation()` for T19 header recovery;
  - `k_reset_steps[]` as the single factory-reset enumeration (new generation,
    pending clear, every key, bond clear) exposed through
    `bridge_config_factory_reset_steps()`;
  - `clear_bonds()` only calls the hook and never touches pairing;
    `clear_pairing()` erases pairing only (not bonds/log).
- `firmware/components/bridge_config/bridge_config_nvs.c` — the only NVS
  opener (`nvs_open`/`nvs_get_blob`/`nvs_set_blob`/`nvs_erase_key`), installs
  `esp_random()`, records `boot_count`/`last_reset_reason` on init, and calls
  `ble_store_clear()` when `CONFIG_BT_NIMBLE_ENABLED` (no-op today). Never opens
  the NimBLE bond namespace.
- `firmware/test/test_bridge_config.c` + host CMake target `bridge-config`:
  RAM KV fake with set-failure injection, deterministic random sequence, bond
  clear spy. Covers fresh init/reload, every active key round-trip, invalid
  writes (range, probes, control/empty ID, bad UTF-8 name, 16-char name, bad
  timeout/units, zero-anchor clock), whole-record validation, reserved Billows
  keys absent before and after factory reset, log clear keeps pairing, forget
  phones keeps pairing, factory reset (generation/pending/keys/bond/version),
  reset-table ordering, single-bad-sector generation stability, v0 migration,
  corrupt version repair, future version refusal/no writes, and argument/null
  handling.
- Docs: design 03 §3.7 implementation notes; ADR 0023.

## Gotchas for later tasks

- **NVS key limit is 15 characters.** The logical keys `display_timeout_s`,
  `last_reset_reason` and `billows_target_f10` cannot be NVS keys. Physical
  aliases are `disp_timeout_s`, `last_reset` and `billows_tgt_f10`. Never add a
  longer key; the core's `_Static_assert`s catch it at host build time.
- All values are **little-endian blobs**; strings are stored without a NUL.
  Use the typed API, not raw keys.
- `config_version` lives in `meta/config_version` (u16, currently 1) and
  survives factory reset. A future layout must add a migration and bump
  `BRIDGE_CONFIG_VERSION`.
- `bridge_config_init()` (firmware) increments `boot_count` and stores
  `esp_reset_reason()` once per boot. Host tests that want that must call
  `bridge_config_stats_note_boot()` explicitly.
- **Generation ordering:** `bridge_config_begin_log_clear()` writes the new
  generation *then* `clear_pending = 1`, so a power cut mid-clear is
  recoverable. T19 must finish the erase while `clear_pending` is true and only
  then call `finish_log_clear()`.
- **Never** call `regenerate_generation()` for one bad sector. Use
  `set_generation()` only to adopt a generation recovered from a sector header.
- `bridge_config_factory_reset()` keeps `meta/config_version`, writes the new
  generation + pending clear, erases pair/device/stats/log-clock keys (including
  reserved Billows keys if a future build wrote them) and clears bonds. It does
  not erase the ring; T19 does that on the pending clear.
- Bond clear is a hook: firmware installs `esp_bond_store_clear()`, which calls
  NimBLE `ble_store_clear()` once `CONFIG_BT_NIMBLE_ENABLED` exists. No other
  component may call it or open the bond namespace.
- `bridge_config_get_reserved_billows()` returns 0/0 and opens nothing. There
  is no setter; T47 must ignore the BLE reserved bytes rather than persist them.
- Core cache is unlocked; single writer per field assumed. T20/T47 must
  serialize if they write from different tasks.

## Follow-ups

- **T16** — after `CONFIRMED`, call `bridge_config_set_pairing()` with the
  learnt `{device_id, frequency_hz, num_probes}`; use `clear_pairing()` for a
  re-pair (keeps bonds/log).
- **T19** — read `clear_pending` from `bridge_config_get_log()` at boot, finish
  the ring erase, then `finish_log_clear()`. Use `begin_log_clear()` for a user
  clear, `regenerate_generation()` only for a wholly unusable log, and
  `set_generation()` to adopt a header-recovered generation.
- **T20** — persist the clock with `bridge_config_clock_set()` at most every
  10 minutes; never per sample.
- **T27/T30** — when NimBLE joins the build, verify
  `CONFIG_BT_NIMBLE_ENABLED` compiles the `host/ble_store.h` branch; keep
  `ble_store_clear()` inside `bridge_config_nvs.c` only. Re-check the no-Wi-Fi
  image-guard conflict recorded in T04.
- **T47** — map the 80-byte BLE config struct to the device getters/setters;
  read-modify-write; ignore the reserved target and refuse non-zero
  `billows_mode` with `unsupported`. Consider a change-notification hook (design
  03 mentions notifications; T15 has none yet).
- **T20/T47** — if config writes move to multiple tasks, add a lock around the
  core cache (ESP-IDF NVS itself is thread-safe).
