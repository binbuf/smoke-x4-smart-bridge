# T08 — CI

## Goal
Put all M0 verification on every pull request: protocol drift, host tests,
firmware build, Flutter analyze/test, UI goldens, and a dependency guard. A
regression or a forbidden dependency fails the build instead of being noticed
later.

## Context (read first)
- Design: [10 §10.1](../design/10-test-and-release.md)
- Verification: **H** (host/CI) · Board required: **no**
- Depends on T02, T03, T04, T05.
- Assumes the commands introduced by those tasks: `make protocol`,
  `make protocol-check`, `ctest`, `idf.py build`, `flutter analyze`,
  `flutter test`, and the screenshot generator.

## Scope
- [x] Add CI job 1: protocol generate + drift check.
- [x] Add CI job 2: C host tests.
- [x] Add CI job 3: firmware build.
- [x] Add CI job 4: Flutter analyze/test, including the UI state matrix and
      layout tests.
- [x] Add CI job 5: UI screenshot/golden check against the approved baseline.
- [x] Add CI job 6: no-network/no-OTA dependency guard (fail if `http`,
      `web_socket`, MQTT, or OTA packages are added to the app/firmware).
- [x] Make all six jobs run on pull requests.

## Out of scope
- Writing the protocol generator or drift check — owned by T02.
- Writing the host tests — owned by T03.
- Firmware or app feature code — T04/T05.
- Deploy, release publishing, signing, or OTA pipelines — outside MVP; no task
  owns them.
- Board/bench verification — T09/T10 (bench tasks are manual, not CI).

## Design notes
- Six jobs, numbered as above; keep their names and intent stable so failures
  are attributable.
- Job 1 must run generation and then the drift check, so stale committed output
  fails.
- Job 6 is a hard guard against the anti-tasks: no `http`, `web_socket`, MQTT,
  or OTA packages in the app or firmware dependency manifests.
- Job 4 includes the UI state matrix and layout tests, not just a plain test
  run.
- Job 5 compares against the approved baseline produced by T06's screenshot
  generator.
- Seed `legacy/` is not built in CI; only the new tree is.

## Done when
- [x] A pull request runs all six jobs.
- [x] CI fails on protocol drift.
- [x] CI fails on a UI regression.
- [x] CI fails on a forbidden dependency.
- [x] Hand-off below filled in.

## Hand-off

### What landed

- `.github/workflows/ci.yml` with six stable, separately attributable jobs on
  every `pull_request` (also `main` pushes and `workflow_dispatch`):
  1. **protocol generate + drift check** — regenerate, `git diff --exit-code --
     protocol/gen`, `make protocol-check`, then C/Dart codec vectors.
  2. **C host tests** — CMake + Ninja + `ctest` on `firmware/test`.
  3. **firmware build** — ESP-IDF 6.0.2 container (`espressif/idf:v6.0.2`),
     `esp32s3`, documented `SDKCONFIG_DEFAULTS`, explicit image-guard re-run and
     firmware artifact upload.
  4. **Flutter analyze/test** — analyze, named `view_state_test.dart` +
     `ui_state_matrix_test.dart`, then the full `flutter test` suite.
  5. **UI screenshot/golden check** — `flutter test
     tool/ui_screenshots_test.dart` on `windows-latest` with pinned Flutter
     3.47.8, matching the host/engine that produced `app/screenshots/`.
  6. **no-network/no-OTA dependency guard** — `tools/ci/check_forbidden_deps.py`
     plus 9 unit tests; rejects direct/resolved transitive app packages, release
     Android network/notification/foreground permissions, ESP-IDF components in
     `idf_component.yml`/`CMakeLists.txt`, and enabled Wi-Fi/IP/HTTP/MQTT/OTA
     Kconfig symbols.
- `app/test/ui_state_matrix_test.dart`: Live, Live offline-cache, History,
  History empty, Settings, Setup and Bridge details at 320/390 dp in dark/light,
  no overflow.
- `app/tool/ui_screenshots_test.dart`: finds the Flutter SDK fonts from
  `FLUTTER_ROOT`, PATH or local defaults, so the golden job is portable.
- Two 320 dp layout fixes surfaced by the matrix: `ProbeCard` trend text now
  ellipsizes in an `Expanded`; the empty History chart uses a minimum height so
  it can grow. No screenshot changed.
- Docs: ADR 0019, design 10 §10.1 CI table, screenshots README, root README CI
  note, and `docs/progress/T08.md`.

### Deviations and boundaries

- Job 5 runs on `windows-latest` by design: the approved baseline was generated
  on Windows with Flutter 3.47.8. Moving it to Linux would need regenerated
  baselines and a new review.
- Job 4 names the existing seam/matrix tests explicitly, then runs the whole
  suite. The full design 13 §13.4 state/copy matrix is still T54; the file name
  and CI step are already in place so coverage cannot silently disappear.
- The two small layout fixes are test-driven robustness changes, not feature
  work; the visual goldens are unchanged.
- The guard checks only `src/main/AndroidManifest.xml`; the debug/profile
  manifests keep INTERNET for the Flutter tool.
- Firmware build is verified locally with the same command; the Docker tag is
  pinned to `v6.0.2`.

### Checks run

```text
python tools/ci/check_forbidden_deps.py            -> ok
python -m unittest discover -s tools/ci ...        -> 9 tests OK
make protocol-check                                -> current
make protocol + git diff -- protocol/gen           -> no drift
make protocol-test (gcc + Dart 3.13.7)             -> C exit 0; Dart passed
make host-test                                     -> 4/4 passed
cd app: flutter analyze                            -> no issues
        flutter test                               -> 54 passed
        flutter test view_state + ui_state_matrix  -> 14 passed
        flutter test tool/ui_screenshots_test.dart -> 29 passed
cd firmware: idf.py build (heltec-v3)              -> complete
             check_image.py                        -> ok, 61 components, no OTA
```

Negative probes (restored afterwards): protocol drift -> exit 2; `http` in app
dependencies -> guard exit 1; swapped `live_dark.png` -> golden exit 1 with 100%
pixel diff. The workflow YAML parses to exactly the six job IDs and has an empty
`pull_request` trigger.

### Next task must know

- Keep the six display names and job IDs stable; failures must stay attributable.
- Keep `protocol/gen` generated-then-diffed in job 1. Do not reorder to
  `protocol-check` only.
- Update `app/test/ui_state_matrix_test.dart` in T54; do not remove it from the
  job 4 command.
- Flutter 3.47.8, Dart 3.13.7 and ESP-IDF 6.0.2 are pinned deliberately.
  Changing them requires updating the workflow and regenerating goldens.
- Any future legitimate network dependency is an ADR-level decision; do not add
  exclusions casually to the guard.
- Board/bench checks remain T09/T10 and are not CI jobs.
