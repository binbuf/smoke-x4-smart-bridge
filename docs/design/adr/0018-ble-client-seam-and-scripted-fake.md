# 0018 - BLE client seam and scripted fake

Status: accepted (T07)

## Context

The BLE contract is owned by `protocol/ble.yaml` and generated into
`protocol/gen/records.dart`. App screens render immutable view state (ADR 0017),
but there was no app-side radio seam and no way to exercise scan, pairing, live
notifications or a disconnect without a phone and a bridge. The firmware lane
and the app lane must stay decoupled while both implement the same contract.

## Decision

- `app/lib/data/ble/ble_client.dart` is the single app-side BLE interface:
  scripted scan stream, connect/disconnect, bond state, MTU request, complete
  characteristic reads/writes, notification subscriptions and named security
  failures (`notConnected`, `notBonded`, ...). Payloads stay raw bytes; the
  interface does not decode probe values.
- `BridgeController` and `createBridgeController` accept an optional `BleClient`.
  `main.dart` is unchanged; production passes none until M2/T32 builds the
  platform adapter.
- The fake lives only under `app/test/support/`: `FakeBleClient` models scripted
  advertisements, connect/bond transitions (including a wrong passkey),
  encryption requirements and notification chunking at `MTU-3`. `FakeBridge`
  implements the GATT server for `info`, `live`, `config`, `stats`, control
  results and a framed `sync_ctrl`/`sync_data` batch. All payloads are built and
  parsed with the generated codecs.
- Tests reach the generated Dart through `app/test/support/codecs.dart`. Dart
  package rules do not let `app/lib/` import `../../protocol/gen`, so the
  production codec import is deferred to M2 rather than copying generated bytes.
- A widget-level `FakeBridgeSession` folds decoded live notifications into the
  controller and maps a fake disconnect to the offline view. It is test support,
  not a production link procedure.

## Consequences

- The acceptance flow (scan → connect → bond → subscribe → live → disconnect)
  runs in `flutter test` with no radio or OS prompt.
- Protocol drift breaks app tests: the fake and tests decode with the generated
  classes.
- T32/T33/T34 replace the test session with the real `BridgeLink`/setup flow.
  T32 must package or relocate the generated Dart codec for `app/lib/`; the
  current test-only wrapper is temporary.
- T64 must prove no `test/support/` import reaches the release graph.
- `BridgeController` owns and disposes an injected client; callers must not also
  own its lifetime.
